开始前准备清单

如果你第一次使用 Mailman，先按这个清单准备。后续接入文档默认你已经有可登录系统、可用邮箱账户和 Bearer Token。

准备项为什么需要最小要求验证方式
运行环境Mailman 前端、后端和数据目录需要稳定运行。Docker、Compose 或已有部署。访问 Web 首页，后端 /api/health 正常。
管理员账号首次进入系统需要创建或登录管理员。记住初始化用户名和密码。POST /api/auth/login 返回 token。
邮箱凭据读取邮件、同步、取件、触发器都依赖邮箱账户。OAuth2 client 或应用专用密码。/api/accounts/verify 成功。
同步策略Mailman 读取数据库中的邮件，触发器也基于已同步邮件。至少同步 INBOX。经典邮件管理器能看到最新邮件。
外部回调地址Webhook、Telegram、业务系统接入需要外部地址。可访问的 HTTPS 或内网地址。用动作测试接口验证返回。

首次启动与登录

Mailman 的前端和后端在一体化镜像中由同一个后端进程提供服务。第一次访问时，登录接口会根据系统状态创建初始管理员账户。

最快体验

docker run -d \
  --name mailman \
  -p 8080:8080 \
  -v mailman_data:/app/data \
  --restart unless-stopped \
  ghcr.io/seongminhwan/mailman-all:latest

访问 http://localhost:8080，使用首次输入的用户名和密码创建管理员。

登录接口

POST/api/auth/login登录并获取 Token
GET/api/auth/me读取当前用户
POST/api/auth/logout退出登录
curl -X POST "$BASE_URL/api/auth/login" \
  -H "Content-Type: application/json" \
  -d '{
    "username": "admin",
    "password": "your-password"
  }'

源码依据：backend/internal/api/router_auth.go、frontend/src/context/auth-context.tsx。

推荐主流程

1
系统配置
先确认系统配置、登录主题、菜单可见性、访问令牌等基础设置。
2
OAuth2 配置
Gmail/Outlook 推荐使用 OAuth2。配置入口对应 /api/oauth2/global-config、/api/oauth2/session/start/{provider}。
3
添加邮箱账户
通过 UI 或 API 添加账户，调用 /api/accounts/verify 检查连通性。
4
配置同步
全局同步配置影响默认行为，账户同步配置覆盖单个账户行为。
5
使用取件和触发器
取件适合“等待一封邮件”，触发器适合“每次收到邮件后自动处理”。
6
沉淀业务资料
把邮箱账户、业务平台账号、2FA、恢复码、标签和代理配置统一管理。

第一次完整闭环

下面这条路线可以验证 Mailman 的核心链路是否跑通：账户接入 → 同步邮件 → 搜索邮件 → 创建触发器 → 测试动作 → 查看日志。

1
OAuth2 配置
进入 OAuth2 配置，新增 Gmail 或 Outlook 凭据，设为启用和默认。
2
添加账户
进入邮箱账户管理，选择 provider，完成授权，保存账户后立即验证。
3
同步邮件
进入同步配置或账户详情，先手动同步 INBOX，确认邮件列表出现新邮件。
4
建立触发器
进入触发器管理，创建一条主题包含关键词的规则，动作先选择打标签或 Webhook。
5
测试并启用
用测试数据确认条件为 true，动作返回 success，再启用触发器。
# 1. 登录
TOKEN=$(curl -s -X POST "$BASE_URL/api/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"your-password"}' | jq -r '.token')

# 2. 查看账户
curl "$BASE_URL/api/accounts/paginated?page=1&limit=20" \
  -H "Authorization: Bearer $TOKEN"

# 3. 验证账户
curl -X POST "$BASE_URL/api/accounts/verify" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"account_id":1}'

# 4. 查看邮件
curl "$BASE_URL/api/account-emails/list/all?limit=20&offset=0" \
  -H "Authorization: Bearer $TOKEN"

# 5. 查看触发器日志
curl "$BASE_URL/api/triggers/logs?limit=20" \
  -H "Authorization: Bearer $TOKEN"
检查点通过标准失败时下一步
登录拿到 Bearer Token，/api/auth/me 返回当前用户。检查用户名密码、初始化状态、登录限流。
账户isVerified 为 true，errorStatus 为 normal。看 OAuth2 配置、应用密码、代理。
同步邮件列表能看到最近邮件，文件夹包含 INBOX。检查同步配置、provider 权限、后端日志。
触发器测试条件返回 result: true，动作测试成功。检查字段名、插件 ID、动作 config。
日志/api/triggers/logs 能看到执行记录。确认触发器启用、邮件确实进入同步和处理流程。
