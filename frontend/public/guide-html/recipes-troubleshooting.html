把 Mailman 的能力组合起来

Mailman 的强大之处在组合：账户、同步、取件、模板、触发器、AI、代理和业务资料可以拼成完整业务流程。本页给出高频配方和排错路径。

组合配方

1
账户配置
接入落件账户，设置 forwardedAddresses。
2
模板配置
取件模板过滤发件域名、主题、时间范围，用正则提取验证码。
3
取件调用
业务侧调用 /api/pickup/poll，传入原始收件地址和模板 ID。

触发器条件命中“重要邮件”后，动作链依次执行：email_forward_action 转发给团队邮箱，telegram_bot_action 通知负责人，email_label_action 打上“已通知”标签。

触发器先用基础条件筛选候选邮件，再调用 ai_process_action 输出分类，之后用 conditional_branch_action 按分类决定 Webhook 目标。

业务账户保存平台账号、2FA 和恢复码；取件模板捕获安全验证邮件；触发器将恢复相关邮件打标签并记录到业务系统。

四个可落地流程

验证码取件 API

  1. 创建或选择取件模板，确认 /api/v2/extractor-templates/test 能输出验证码。
  2. 业务系统发起登录或注册动作，并记录发起时间。
  3. 调用 /api/pickup/poll，传入 account_id、to_query、since 和 template_id。
  4. 读取 extractions[0].extracted_value，失败时记录 new_count 和 status。
curl -X POST "$BASE_URL/api/pickup/poll" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "account_id": 12,
    "to_query": "login@example.com",
    "since": "2026-05-31T10:00:00Z",
    "keep_alive_seconds": 90,
    "sync_interval": 5,
    "template_id": 3
  }'

重要邮件通知

  1. 用过滤器模板定义“重要邮件”，例如发件域、关键词、收件地址。
  2. 创建触发器并添加 Webhook、Telegram、邮件转发动作。
  3. 增加全局日志拦截器，只记录通知类动作。
  4. 通过 /api/v2/triggers/test-complete 完整测试。
curl -X POST "$BASE_URL/api/v2/triggers/test-complete" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "email_id": 8891,
    "expressions": { "type": "group", "operator": "and", "conditions": [] },
    "actions": [
      { "id": "notify", "pluginId": "webhook_action", "enabled": true, "executionOrder": 1, "config": {} }
    ]
  }'

AI 分类分流

  1. 创建 AI 配置并测试通过。
  2. 用 ai_process_action 输出分类 JSON。
  3. 用 conditional_branch_action 根据分类选择不同 Webhook。
  4. 用 email_label_action 或账户标签把结果沉淀下来。
curl -X POST "$BASE_URL/api/openai/call" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "config_id": 1,
    "system_prompt": "只输出 JSON: {\"category\":\"login|invoice|security|other\"}",
    "user_message": "Subject: Your login code\nBody: Your code is 123456",
    "response_format": "json"
  }'

业务账号恢复

  1. 创建业务模块和业务账户，保存登录地址、用户名、2FA、恢复码。
  2. 把业务账户绑定到邮箱账户，后续按邮箱反查业务资产。
  3. 创建安全邮件触发器，命中后打标签并通知负责人。
  4. 恢复完成后在业务账户备注中记录处理结果。
curl "$BASE_URL/api/accounts/12/business-accounts" \
  -H "Authorization: Bearer $TOKEN"

常见问题排查

OAuth2 授权失败

  • 确认回调地址为 {BACKEND_URL}/api/oauth2/callback/{provider}。
  • Gmail 测试模式需要把邮箱加入测试用户。
  • 确认 provider API 已启用，scope 与系统配置一致。
  • 检查账户 errorStatus 是否为 oauth_expired 或 auth_revoked。

取件超时

  • 先手动调用 /api/accounts/{id}/sync-now 验证同步是否正常。
  • 检查搜索条件：收件地址、主题、发件域名、时间范围。
  • 确认转发地址已绑定到账户。
  • 查看取件模板调试结果和提取日志。

触发器没有执行

  • 确认触发器 enabled 为 true。
  • 使用 /api/v2/triggers/test-condition 单独测试条件。
  • 查看 /api/triggers/logs 是否有执行记录。
  • 检查动作插件配置是否通过 UI Schema 校验。

代理不生效

  • 测试代理池条目 /api/proxy-pool/{id}/test。
  • 检查账户 proxyMode 和 proxyFallbackMode。
  • 自动匹配时确认分组和标签条件能匹配到可用代理。
  • Webhook 动作如果单独配置代理，需要同时检查动作配置。

诊断树

症状第一层检查第二层检查最后确认
取件返回 0 封邮件/api/accounts/{id}/sync-now 是否成功/api/emails/search 放宽条件能否搜到since、to_query、转发地址是否正确
取件有邮件但无提取/api/v2/extractor-templates/debug 表达式是否命中动作链变量名和 outputConfig.field 是否一致正则是否匹配纯文本正文而不是 HTML
触发器条件通过但动作失败/api/v2/triggers/test-action 单测动作/api/plugins/ui/schemas 对照配置字段查看 /api/triggers/logs 和拦截器日志
AI 动作失败/api/openai/test-config 是否通过模型、base_url、headers 是否与 provider 匹配Prompt 是否要求 JSON 但模型返回文本
代理链路失败/api/proxy-pool/{id}/test 是否通过账户 proxyMode 和自动匹配条件是否正确Webhook 动作是否覆盖了单独代理配置
收集问题时至少带上：账户 ID、邮件 ID、触发器 ID、模板 ID、动作插件 ID、拦截器 ID、调用时间和完整响应。这样能把排查从“猜”变成“定位”。

遇到复杂问题时，优先收集：账户 ID、邮件 ID、触发器 ID、模板 ID、日志 ID 和后端日志时间段。
