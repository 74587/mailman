从 0 到 1 组织运营资产

这组能力用来把“邮箱”提升成“可运营的业务资产”：AI 负责理解内容，业务账户保存平台资料，标签负责分层，代理池负责网络出口。

1
先接 AI 配置
保存至少一个可用模型配置，并用 /api/openai/test-config 验证。
2
建立业务模块
为 GitHub、Shopify、Stripe 等平台创建业务模块，定义登录地址和自定义字段。
3
绑定业务账户与邮箱账户
业务账户通过 emailAccountId 关联邮箱，方便从邮箱回查平台账号。
4
用标签和代理分层
账户标签按业务、地区、风险分类；代理池按地区、质量、用途分类，并给账户配置代理策略。

AI 配置与 Prompt 模板

AI Provider 配置

通过 Web 界面或 API 保存 API Key、Base URL、模型等配置。AI 动作插件会使用这些配置处理邮件。

GET/api/openai/configs配置列表
POST/api/openai/configs创建配置
POST/api/openai/test-config测试配置

Prompt 模板

用于生成提取模板、摘要、分类和结构化字段。支持初始化默认模板和自定义模板。

GET/api/openai/prompt-templates模板列表
POST/api/openai/initialize-templates初始化默认模板
POST/api/openai/generate-template生成模板
POST/api/openai/call直接调用 AI

创建 AI Provider 配置

curl -X POST "$BASE_URL/api/openai/configs" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "production-openai",
    "channel_type": "openai",
    "base_url": "https://api.openai.com/v1",
    "api_key": "sk-***",
    "model": "gpt-4o-mini",
    "headers": {},
    "is_active": true
  }'

curl -X POST "$BASE_URL/api/openai/test-config" \

业务模块与业务账户

业务模块定义平台类型，业务账户保存具体账号资料。业务账户可绑定邮箱账户，形成“一个邮箱承载哪些平台账号”的运营视图。

对象关键字段接口
业务模块name、website、loginUrl、logo、fieldSchema、statusOptions/api/business-modules
业务账户emailAccountId、moduleId、username、password、totpSecret、recoveryCodes、customFields/api/business-accounts
账户关联查询按邮箱账户查看关联业务账户/api/accounts/{id}/business-accounts
 
curl -X POST "$BASE_URL/api/business-accounts" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "emailAccountId": 12,
    "moduleName": "GitHub",
    "displayName": "GitHub US",
    "username": "octo@example.com",
    "totpSecret": "BASE32SECRET",
    "recoveryCodes": ["code-1", "code-2"],
    "status": "active"
  }'

curl -X POST "$BASE_URL/api/business-modules" \

标签组与账户打标

标签组

标签组支持 single 单选和 multiple 多选，适合“地区”“用途”“风险等级”等不同维度。

代理池与账户代理

代理池保存可复用代理，账户可选择手动代理、指定代理池条目或自动匹配代理。Webhook 动作也支持代理配置。

需要从 0 到 1 配置代理列表、HTTP/SOCKS5 网关、安全策略、DNS 策略、网关用户和 curl/浏览器接入时，请阅读独立专题：代理池管理与代理网关接入。

代理类型

http、https、ssh、socks5。

账户模式

manual、selected、auto。

回退策略

interrupt、manual_backup、auto_select。

GET/api/proxy-pool代理列表
POST/api/proxy-pool/bulk-import批量导入
POST/api/proxy-pool/{id}/test测试代理
POST/api/proxy-pool/select选择代理
GET/api/proxy-groups代理分组
GET/api/proxy-tags代理标签

创建代理分组并导入代理

curl -X POST "$BASE_URL/api/proxy-groups" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "name": "US Residential", "description": "美国住宅代理", "color": "#0f766e" }'

curl -X POST "$BASE_URL/api/proxy-tags" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "name": "login", "color": "#2563eb" }'

curl -X POST "$BASE_URL/api/proxy-pool/bulk-import" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "defaultType": "socks5",
    "groupId": 1,
    "tagIds": [1],
    "checkProxy": true,
    "channel": "default",
    "duplicatePolicy": "skip",
    "content": "127.0.0.1:1080:user:pass\n127.0.0.2:1080:user:pass"
  }'

组合玩法

触发器条件命中邮件后，执行 ai_process_action 生成分类，再用 email_label_action 打标签，最后 webhook_action 推给业务系统。

业务账户保存登录站点、用户名、2FA 和恢复码；取件模板等待安全邮件；触发器将恢复邮件归档并提醒运营人员。

账户按地区标签分组，代理池按地区/质量打标，账户代理使用自动匹配，失败后按回退策略切换备用代理。

源码校验：openai_handlers.go、business_account.go、tag.go、proxy_pool.go
