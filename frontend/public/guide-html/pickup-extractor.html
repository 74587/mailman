Pickup & Extractor V2

等待一封邮件，并把需要的数据提取出来

取件是 Mailman 面向验证码、登录确认、一次性通知的核心能力。新版 /api/pickup/poll 会把临时同步、邮件搜索、模板匹配、动作链提取组合成一次请求。

打开取件

从 0 到 1 接入取件

取件不是单纯搜索邮件，而是一条完整链路：账户能收信、同步能拉取、搜索条件能定位、提取规则能输出目标值。上线前建议按下面顺序逐步确认。

1
确认落件账户
先完成 OAuth2 或 IMAP 账户接入，并在邮件管理中能看到最新邮件。转发型业务要把原始收件地址维护到账户的 forwardedAddresses。
2
确认同步能力
手动调用 POST /api/accounts/{id}/sync-now，再用 GET /api/emails/search 验证邮件能被搜索到。
3
选择提取模式
长期复用选 template_id；业务方希望一次请求内声明规则选 inline_actions；只提一个验证码选 simple_extract。
4
业务侧轮询取件
调用 POST /api/pickup/poll，让 Mailman 在 keep_alive_seconds 时间窗口内启用临时同步并返回提取结果。
取件服务的请求结构来自 backend/internal/services/pickup_service.go 的 PickupPollRequest。搜索条件目前支持 account_id、to_query、since 和 limit；主题、发件人、正文等更细条件应放在模板 expressions 里。

统一取件接口

POST /api/pickup/poll 适合“我现在要等一封邮件”的场景。它会根据请求参数选择账户、设置临时同步、轮询邮件、执行取件模板，并返回最终提取结果。

字段类型说明建议
account_idnumber目标邮箱账户 ID。可选但推荐传；如果 to_query 能解析到账户，后端会记录解析来源。生产调用固定传入，避免多账户模糊匹配。
keep_alive_secondsnumber临时同步覆盖有效期，默认 30 秒。验证码场景常用 60-120 秒。
sync_intervalnumber取件期间后端拉取邮件间隔，默认 5 秒。不要长期设太低；只在取件窗口内加速。
sincestringRFC3339 起始时间，只搜索该时间之后的邮件。业务侧在发起登录请求前记录当前时间。
to_querystring收件人模糊匹配，适合原始收件地址或别名。转发落件场景必须传原始业务邮箱。
limitnumber候选邮件数量，默认 10。通常 5-20 即可。
template_idnumber引用已有取件模板 V2。适合稳定业务。
inline_actionsobject请求内声明表达式、动作链和 output_config。适合外部系统动态生成规则。
simple_extractobjectV1 风格的简单提取配置。适合从正文或主题取一个值。
 
curl -X POST "$BASE_URL/api/pickup/poll" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "account_id": 12,
    "to_query": "login@example.com",
    "since": "2026-05-31T10:00:00Z",
    "keep_alive_seconds": 90,
    "sync_interval": 5,
    "limit": 10,
    "template_id": 3
  }'
如果邮件是先转发到落件账户，再由业务侧按原始收件地址取件，请优先维护账户的 forwardedAddresses，并在取件时传入原始地址作为 to_query。

三种取件模式怎么选

先在 Mailman 中创建取件模板 V2，业务侧只传 template_id。模板可以复用表达式系统、动作插件、日志和统计，是最推荐的生产方式。

{
  "account_id": 12,
  "to_query": "login@example.com",
  "since": "2026-05-31T10:00:00Z",
  "keep_alive_seconds": 90,
  "sync_interval": 5,
  "template_id": 3
}

请求中直接带 expressions、actions 和 output_config。注意这里的字段名是 output_config，它来自 InlineActionsConfig；模板管理接口里则是 outputConfig。

{
  "account_id": 12,
  "to_query": "login@example.com",
  "keep_alive_seconds": 60,
  "inline_actions": {
    "expressions": {
      "type": "group",
      "operator": "and",
      "conditions": [
        { "type": "condition", "field": "subject", "operator": "contains", "value": "code" }
      ]
    },
    "actions": [
      {
        "id": "extract-code",
        "pluginId": "variable_extract_action",
        "pluginName": "变量提取",
        "enabled": true,
        "executionOrder": 1,
        "config": {
          "source": "email",
          "source_field": "text_body",
          "expression_type": "regex",
          "expression": "\\d{6}",
          "return_type": "string"
        }
      }
    ],
    "output_config": { "format": "text", "field": "extract-code" }
  }
}

只需要一个正则或简单脚本时使用 simple_extract，字段由 SimpleExtractConfig 定义：field、type、pattern、match_mode、match_index。

{
  "account_id": 12,
  "to_query": "login@example.com",
  "keep_alive_seconds": 60,
  "simple_extract": {
    "field": "body",
    "type": "regex",
    "pattern": "\\b\\d{6}\\b",
    "match_mode": "first"
  }
}

取件模板 V2 的结构

过滤条件

字段 expressions 复用触发器表达式系统，用来判断当前邮件是否匹配模板。

{
  "type": "group",
  "operator": "and",
  "conditions": [
    { "type": "condition", "field": "subject", "value": "code" },
    { "type": "plugin", "pluginId": "email_time_range", "fields": { "range": "10m" } }
  ]
}

提取动作链

字段 actions 按 executionOrder 执行，常用变量提取、AI 处理、数据转换 V2 和中断流程。

[
  {
    "id": "extract-code",
    "pluginId": "variable_extract_action",
    "pluginName": "变量提取",
    "enabled": true,
    "executionOrder": 1,
    "config": {
      "source": "email",
      "source_field": "text_body",
      "expression_type": "regex",
      "expression": "\\d{6}",
      "return_type": "string"
    }
  }
]

创建一个可复用验证码模板

curl -X POST "$BASE_URL/api/v2/extractor-templates" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "GitHub 登录验证码",
    "description": "匹配 GitHub 登录验证邮件并返回 6 位验证码",
    "enabled": true,
    "category": "验证码",
    "tags": ["github", "login"],
    "expressions": {
      "type": "group",
      "operator": "and",
      "conditions": [
        { "type": "condition", "field": "from", "operator": "contains", "value": "github.com" },
        { "type": "condition", "field": "subject", "operator": "contains", "value": "code" }
      ]
    },
    "actions": [
      {
        "id": "extract-code",
        "pluginId": "variable_extract_action",
        "pluginName": "变量提取",
        "enabled": true,
        "executionOrder": 1,
        "config": {
          "source": "email",
          "source_field": "text_body",
          "expression_type": "regex",
          "expression": "\\b\\d{6}\\b",
          "return_type": "string"
        }
      }
    ],
    "outputConfig": {
      "format": "text",
      "field": "extract-code",
      "description": "返回验证码字符串"
    }
  }'

模型依据：backend/internal/models/extractor_template_v2.go 中的 ExtractorTemplateV2、ExtractionLogV2、ExtractionResult。

取件常用动作链

  1. 过滤发件域名、主题关键字、收件地址和时间范围。
  2. 使用 variable_extract_action 从 text_body 或 subject 通过正则提取 \\d{6}。
  3. 输出配置选择 text，直接返回验证码字符串。
  1. 先用 email_transform_action_v2 清洗正文、去掉多余链接或签名。
  2. 用多条 variable_extract_action 提取 code、source、expire_at。
  3. 输出配置选择 json 或 object。
  1. 通过 ai_process_action 要求模型从邮件中提取目标字段。
  2. 再用 variable_extract_action 从变量池读取 AI 输出并做 JSONPath 提取。
  3. 适合格式经常变化、正则难维护的邮件。
插件用途源码
variable_extract_action从邮件、变量或表达式中提取最终值variable_extract_action.go
email_transform_action_v2多规则转换，支持模板、JavaScript、正则、前后缀和替换email_transform_action_v2.go
conditional_branch_action根据条件走不同动作分支conditional_branch_action.go
parallel_actions并行执行多个动作parallel_actions.go
return_action中断后续流程并返回值return_action.go

输出格式

text

返回纯文本，适合验证码、链接、单个 ID。

json

返回 JSON 字符串，适合 API 调用方直接解析。

array

返回数组，适合提取多个链接、多个订单号。

object

返回结构化对象，适合业务系统消费。

取件响应怎么读

{
  "success": true,
  "account_id": 12,
  "requested_account_id": 12,
  "resolved_by": "account_id",
  "new_count": 1,
  "sync_active": true,
  "sync_expires_at": "2026-05-31T10:01:30Z",
  "emails": [{ "id": 8891, "subject": "Your login code" }],
  "extractions": [
    {
      "email_id": 8891,
      "success": true,
      "status": "success",
      "extracted_value": "123456"
    }
  ]
}
响应字段含义接入方处理建议
success取件请求是否成功处理。false 时读取顶层错误或提取项 error。
new_count候选邮件数量。为 0 通常是同步未拉到或搜索条件过窄。
sync_active临时同步是否仍在有效窗口内。业务侧可在窗口内继续请求，避免重复创建覆盖。
extractions[].statussuccess、failed、no_match、skipped。no_match 优先检查表达式；failed 查看模板日志。

调试一封样例邮件

在真正接入业务系统之前，先用模板调试接口确认表达式命中、动作链输出和最终格式。调试请求可以使用现有邮件 ID，也可以传 customEmail 构造一封样例邮件。

测试已有邮件

curl -X POST "$BASE_URL/api/v2/extractor-templates/3/execute" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "emailId": 8891 }'

逐步调试配置

curl -X POST "$BASE_URL/api/v2/extractor-templates/debug" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "emailId": 8891,
    "stepByStep": true,
    "expressions": { "type": "group", "operator": "and", "conditions": [] },
    "actions": [],
    "outputConfig": { "format": "text" }
  }'
如果 /api/pickup/poll 超时，先不要改正则。按顺序检查：账户同步状态、to_query 是否能命中、since 是否晚于邮件时间、模板表达式是否过窄、动作链是否返回了目标变量。
