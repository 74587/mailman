把通用逻辑从单个触发器中抽出来

从 0 到 1 使用拦截器和模板

触发器动作链解决“某封邮件命中后做什么”，拦截器解决“所有动作执行前后都要遵守什么规则”。模板则把稳定的表达式和动作配置沉淀下来，避免每个触发器重复配置。

1
先沉淀模板
把常用条件保存为过滤器模板，把常用动作链保存为动作模板。模板字段来自 FilterTemplate 和 ActionTemplate。
2
再配置触发器
触发器可以引用这些模板创建条件和动作，减少手工复制。
3
加全局拦截器
用 scope=global 对所有动作做审计、日志、统一变量检查或跳过策略。
4
必要时加局部拦截器
用 scope=local 并设置 trigger_id 或 extractor_id，只影响某条触发器或模板。
推荐顺序：先用模板复用业务规则，再用拦截器做平台级治理。模板负责“少配错”，拦截器负责“统一兜底”。

拦截器如何工作

1
选择作用域
global 表示全局拦截器，local 表示绑定特定触发器或提取器。
2
选择阶段
before 在动作前执行，可跳过或改写；after 在动作后执行，可审计或补充通知。
3
设置过滤
按动作类型 include/exclude，或使用高级表达式过滤。
4
记录日志
每次拦截执行会写入拦截器日志，用于回溯和排错。

模型依据：backend/internal/models/interceptor.go。

创建一个全局审计拦截器

下面示例使用内置 logging_interceptor。可用插件和默认配置以 GET /api/interceptors/plugins 返回为准，配置 schema 来自插件的 ConfigSchema。

curl "$BASE_URL/api/interceptors/plugins" \
  -H "Authorization: Bearer $TOKEN"

curl -X POST "$BASE_URL/api/interceptors" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "全局动作审计",
    "description": "记录 Webhook、转发、AI 等动作执行输入输出和耗时",
    "plugin_id": "logging_interceptor",
    "plugin_config": {
      "log_level": "info",
      "log_input": true,
      "log_output": true,
      "log_action_config": false,
      "log_duration": true,
      "log_variables": false,
      "max_data_length": 10000,
      "retention_days": 30
    },
    "scope": "global",
    "enabled": true,
    "order": 10,
    "phases": { "before": true, "after": true },
    "filter": {
      "mode": "include",
      "action_types": ["webhook_action", "ai_process_action", "email_forward_action"]
    },
    "error_handling": {
      "before_error_policy": "continue",
      "after_error_policy": "continue",
      "max_retries": 1,
      "retry_delay_seconds": 2
    },
    "skip_config": {
      "skip_behavior": "continue",
      "execute_after_on_skip": true,
      "log_skipped": true
    },
    "execution": {
      "after_mode": "async",
      "async_config": {
        "queue_name": "interceptor-audit",
        "timeout_seconds": 30,
        "max_concurrency": 10,
        "retry_on_error": true,
        "max_retries": 2
      }
    }
  }'
字段何时必填说明
plugin_id创建时必填拦截器插件 ID，例如 logging_interceptor。
scope创建时必填global 影响所有动作；local 必须绑定触发器或提取器。
trigger_id / extractor_id局部拦截器二选一，用于限定作用域。
order可选数字越小越早执行；可通过 PUT /api/interceptors/order 批量调整。
phases必填至少启用 before 或 after 之一。
filter可选按动作插件类型 include/exclude，或启用高级表达式。

策略字段

字段可选值说明
phases.before / phases.aftertrue / false控制前置和后置阶段是否启用。
filter.modeall、include、exclude控制拦截器命中的动作范围。
before_error_policyabort、continue、skip_action前置阶段出错后的处理方式。
after_error_policyabort、continue、skip_action后置阶段出错后的处理方式。
skip_behaviorcontinue、abort跳过当前动作后是继续还是中断动作链。
after_modesync、async后置阶段同步执行或异步执行。

日志和统计类拦截器建议 before_error_policy=continue、after_error_policy=continue，避免审计失败影响业务动作。

风控、限流、黑名单类拦截器建议放在 before，需要阻断时返回 skip_action 或 abort，并将 log_skipped 打开。

后置通知、指标上报、外部审计建议 after_mode=async，并配置 queue_name、timeout_seconds、max_concurrency。

过滤器模板与动作模板

过滤器模板

用于复用常见筛选条件，例如“来自 GitHub 且主题包含 code”、“最近 10 分钟内的登录邮件”。

GET/api/filter-templates列表
POST/api/filter-templates创建
GET/api/filter-templates/categories分类
POST/api/filter-templates/{id}/increment-usage使用计数

动作模板

用于复用动作配置，例如“Webhook 推送到业务系统”、“Telegram 通知管理员”、“AI 摘要后打标签”。

GET/api/action-templates列表
POST/api/action-templates创建
GET/api/action-templates/categories分类
POST/api/action-templates/{id}/increment-usage使用计数
推荐把“业务稳定规则”沉淀成模板，把“系统统一行为”沉淀成拦截器。模板解决复用，拦截器解决治理。

过滤器模板 JSON

curl -X POST "$BASE_URL/api/filter-templates" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "GitHub 登录邮件",
    "description": "来自 GitHub 且主题包含 code",
    "category": "验证码",
    "tags": ["github", "login"],
    "expressions": {
      "type": "group",
      "operator": "and",
      "conditions": [
        { "type": "condition", "field": "from", "operator": "contains", "value": "github.com" },
        { "type": "condition", "field": "subject", "operator": "contains", "value": "code" }
      ]
    }
  }'

动作模板 JSON

curl -X POST "$BASE_URL/api/action-templates" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Webhook 推送验证码",
    "description": "把提取值推送给业务系统",
    "category": "Webhook",
    "tags": ["webhook", "code"],
    "actions": [
      {
        "id": "send-code",
        "pluginId": "webhook_action",
        "pluginName": "Webhook 调用",
        "enabled": true,
        "executionOrder": 1,
        "config": {
          "url": "https://api.example.com/mailman/code",
          "method": "POST",
          "headers": { "Content-Type": "application/json" },
          "body": "{\"email_id\":\"{{email.id}}\",\"subject\":\"{{email.subject}}\"}"
        }
      }
    ]
  }'

日志与回溯

拦截器日志记录每次动作被拦截时的阶段、动作插件、执行结果、错误和决策。它是排查“为什么动作被跳过或中断”的第一入口。

查看日志列表

curl "$BASE_URL/api/interceptors/logs?interceptor_id=1&limit=50" \
  -H "Authorization: Bearer $TOKEN"

查看日志统计

curl "$BASE_URL/api/interceptors/logs/stats?interceptor_id=1" \
  -H "Authorization: Bearer $TOKEN"
现象优先查看下一步
动作被跳过decision_made、phase检查前置拦截器返回和 skip_config。
动作链中断error_message、before_error_policy如果是治理策略故意中断，补充提示；如果是插件异常，调低策略为 continue 后再排查。
日志太多filter.mode、action_types用 include 只记录关键动作，或关闭 log_input、log_output。
