Proxy Pool & Gateway

从代理资产到 HTTP / SOCKS5 网关的完整接入手册

这份手册按真实配置顺序讲解：先维护上游代理，再创建 Mailman 代理网关，配置安全、DNS、用户名路由和网关用户，最后用 curl、浏览器、Playwright 或业务程序接入代理。

先理解资源层级

代理池管理模块不是简单的“保存代理”。它有三个顶级资源：代理、网关、网关用户；用户名路由、安全策略和 DNS 策略都属于具体网关。

层级资源作用
顶级代理列表保存上游 HTTP、SOCKS5、SSH 等代理，是真实访问目标网站的出口。
顶级代理网关Mailman 自己监听的 HTTP / SOCKS5 / Mixed 代理入口。
顶级网关用户外部客户端连接 Mailman 代理网关时使用的账号，独立于 Mailman 登录账号。
网关级用户名路由用户通过用户名后缀临时切换不同代理池、fallback、安全或 DNS 策略。
网关级安全策略限制来源 IP、目标 Host、目标端口，并阻断内网、回环和 metadata 地址。
网关级DNS 策略控制远端解析、本地解析、自定义 resolver、缓存 TTL 和 DNS 安全检查。
用户级账号分组 / 标签单独维护，再在创建网关用户时选择，用于权限和运营分层。
1
客户端连接 Mailman 网关
客户端使用 HTTP、SOCKS5 或 Mixed 端口，并提交网关用户名和密码。
2
认证和授权
Mailman 校验网关用户、可用网关、用户名路由权限和账号限制。
3
安全与 DNS 检查
按网关或路由策略检查来源、目标、端口和解析结果。
4
选择上游代理
按代理范围、调度算法、fallback 和粘性策略从代理池中选择真实出口。

第一步：维护上游代理

先进入“代理池管理 → 代理列表”，把上游代理按分组和标签整理好。网关用户和路由策略后续都会从这些代理中选择。

分组

主分类，例如 US Residential、SG Datacenter、Backup Pool。

标签

多维标记，例如 login、scraping、high-quality、warmup。

检测

导入后立即测试，记录状态、延迟、出口 IP、国家、地区、城市和 ISP。

批量导入格式

host:port
host:port:username:password
username:password@host:port
socks5://username:password@host:port
http://username:password@host:port

API 示例

curl -X POST "$BASE_URL/api/proxy-groups" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "name": "US Residential", "description": "美国住宅代理", "color": "#0f766e" }'

curl -X POST "$BASE_URL/api/proxy-tags" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "name": "login", "color": "#2563eb" }'

curl -X POST "$BASE_URL/api/proxy-pool/bulk-import" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "defaultType": "socks5",
    "groupId": 1,
    "tagIds": [1],
    "checkProxy": true,
    "channel": "default",
    "duplicatePolicy": "skip",
    "content": "127.0.0.1:1080:user:pass\n127.0.0.2:1080:user:pass"
  }'
生产建议先小批量导入并检测，再按地区、用途和质量扩大导入范围。

第二步：创建代理网关

代理网关是 Mailman 对外暴露的代理入口。客户端看到的是 Mailman 的地址，实际出口由 Mailman 从代理池中选择。

字段推荐值说明
监听 IP127.0.0.1 / 内网 IP / 0.0.0.0公网或全网卡监听必须显式确认公开监听。
外部访问地址proxy.example.com不做校验，只用于生成示例 curl。
外部访问端口32027 或留空Docker、Kubernetes、负载均衡端口映射时填写；留空则使用监听端口。
监听端口32109Mailman 进程实际监听的端口。
协议mixed同一端口支持 HTTP 和 SOCKS5，推荐。
需要认证开启公网监听不允许关闭认证。
默认安全策略选择网关级策略控制访问安全边界。
默认 DNS 策略选择网关级策略控制解析方式。

HTTP

适合 HTTP 代理和 HTTPS CONNECT。curl 使用 -x http://...。

SOCKS5

适合浏览器、爬虫和自动化工具。curl 使用 --socks5-hostname。

Mixed

同一端口自动识别 HTTP 或 SOCKS5，是最省端口的方式。

保存网关后需要进入网关概览点击“热加载”，监听端口才会按最新配置启动或重建。

第三步：配置安全、DNS 和用户名路由

安全策略用于防止代理入口变成 SSRF 或开放代理。生产环境建议开启内网、回环、链路本地、多播、metadata 地址阻断和 DNS rebinding 防护。

配置建议说明
来源允许 CIDR203.0.113.20/32只允许指定客户端连接。
目标端口允许80、443只允许 Web 目标。
Host allowlist*.example.com限制只能访问指定业务域名。
未匹配动作deny没有命中允许规则时拒绝。

DNS 策略决定域名在哪里解析，以及解析结果如何参与安全检查。

字段生产建议说明
解析模式远端解析减少本地 DNS 泄露，适合代理访问外网。
SOCKS5 远端解析开启关闭时 Mailman 会先本地解析。
HTTP CONNECT 保留 Host开启本地解析成 IP 后仍保留原始 Host 头。
安全预解析开启远端解析模式也先解析目标，用于安全策略。
多 IP 策略全部检查所有解析 IP 都必须通过安全检查。
解析失败动作拒绝生产不建议 remote fallback。

用户名路由允许用户在用户名后携带标志号，临时切换策略。标志号会在页面中显示，用户必须被授权才能使用。

proxy_user#17
proxy_user?route=17
proxy_user?rs=17
proxy_user?strategy=17
proxy_user#17;purpose=signup;batch=202606
  • 网关用户必须开启“允许用户名携带路由标志”。
  • 网关用户必须被授权使用当前网关。
  • 网关用户必须被授权使用该路由策略，或开启“允许全部路由策略”。
  • 未携带标志号时，使用网关用户自己的默认策略。

第四步：创建网关用户

网关用户是外部客户端连接 Mailman 代理网关时使用的账号。它和 Mailman 登录账号完全独立。

账号与授权

用户名和密码可一键生成；分组和标签从已有项中搜索选择；可用网关通过搜索下拉选择后以标签回显。

代理选择

支持全部可用、按组/标签、临时代理池。临时代理池通过代理列表子弹窗筛选并多选。

策略选项建议
调度算法随机、轮询、权重、最低延迟、优先复用最近成功通用场景用随机或轮询；会话稳定场景用优先复用。
粘性策略账号、客户端 IP、目标域名、客户端 IP + 目标域名登录和浏览器会话建议按账号或客户端 IP 粘性。
Fallback中断、重试换代理、备用池、直连生产谨慎开启直连 fallback。
限速最大并发、每分钟连接数、带宽、最大会话时长外部用户必须设置合理限制。
创建完成后，在网关用户列表点击“代码示例”，选择可用网关，页面会实时拉取网关信息并生成代理 URL、curl 和程序接入片段。

第五步：客户端接入代理

完整代理 URL

适合粘贴到需要 scheme://username:password@host:port 的工具里。用户名或密码包含 #、?、空格等字符时，需要按 URL 规则编码。

http://gw_user:gw_password@proxy.example.com:32109
socks5://gw_user:gw_password@proxy.example.com:32109

# 用户名路由示例，gw_user#17 需要编码为 gw_user%2317
http://gw_user%2317:gw_password@proxy.example.com:32109
socks5://gw_user%2317:gw_password@proxy.example.com:32109

curl

curl 示例使用 --proxy-user 传递原始用户名密码，不要把密码里的 } 写成 %7d 这类 URL 编码。

# HTTP CONNECT
curl -x 'http://proxy.example.com:32109' \
  --proxy-user 'gw_user:gw_password' \
  'https://api.ipify.org?format=json'

# HTTP CONNECT + 用户名路由
curl -x 'http://proxy.example.com:32109' \
  --proxy-user 'gw_user#17:gw_password' \
  'https://api.ipify.org?format=json'

# SOCKS5 远端解析
curl --socks5-hostname 'proxy.example.com:32109' \
  --proxy-user 'gw_user:gw_password' \
  'https://api.ipify.org?format=json'

# SOCKS5 + 用户名路由
curl --socks5-hostname 'proxy.example.com:32109' \
  --proxy-user 'gw_user#17:gw_password' \
  'https://example.com'

Playwright

import { chromium } from 'playwright'

const browser = await chromium.launch({
  proxy: {
    server: 'http://proxy.example.com:32109',
    username: 'gw_user#17',
    password: 'gw_password',
  },
})

const page = await browser.newPage()
await page.goto('https://api.ipify.org?format=json')
console.log(await page.textContent('body'))
await browser.close()

Python requests

import requests
from urllib.parse import quote

username = quote("gw_user#17", safe="")
password = quote("gw_password", safe="")
proxy = f"http://{username}:{password}@proxy.example.com:32109"

proxies = { "http": proxy, "https": proxy }
print(requests.get("https://api.ipify.org?format=json", proxies=proxies, timeout=20).text)

邮箱账户如何使用代理池

代理池也能给邮箱账户使用。邮箱账户代理主要用于 IMAP、SMTP、OAuth2 等邮箱访问；代理网关则用于对外提供通用 HTTP / SOCKS5 入口。

手动代理

直接填写 socks5://user:pass@host:port。

指定代理

从代理池中选择一个固定代理条目。

自动匹配

按代理分组和标签自动选择可用代理。

账户代理 fallback 支持 interrupt、manual_backup 和 auto_select。邮箱登录、同步或取件失败时，先看账户错误状态，再看代理检测状态。

排查手册

现象优先检查
连接网关失败网关是否启用、是否热加载、端口是否被占用、防火墙是否放行。
认证失败用户名密码、账号是否启用/过期、是否授权当前网关、路由标志是否授权。
没有可用代理代理状态、账号选择范围、分组标签、临时代理池和 fallback 配置。
被安全策略拒绝来源 CIDR、目标 Host、目标端口、内网/回环/metadata 阻断。
DNS 失败DNS 模式、自定义 resolver、解析失败动作、DNS rebinding 防护。
HTTP 可用但 SOCKS5 不可用网关协议是否支持 SOCKS5，客户端是否使用 --socks5-hostname。
SOCKS5 可用但 HTTP 不可用网关协议是否支持 HTTP，目标端口 443 是否允许。

上线安全清单

  • 公网监听必须开启认证，并配置来源 CIDR 或外层防火墙。
  • 默认安全策略开启内网、回环、链路本地、多播、metadata 阻断。
  • 开启 DNS rebinding 防护，解析失败动作使用拒绝。
  • 普通用户不要授权全部网关或全部路由策略。
  • 不要默认开启直连 fallback。
  • 外部用户设置过期时间、最大并发、每分钟连接数和最大会话时长。
