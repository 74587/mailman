Sync & Mailbox

把邮箱邮件稳定同步到 Mailman

同步系统负责把 provider 邮件拉取到本地数据库，邮件管理器和搜索接口都读取本地数据。全局配置设默认规则，账户配置覆盖单个账户，临时同步用于取件等短时间高频场景。

打开同步配置

从 0 到 1 配好同步

同步是邮件管理、取件、触发器的共同地基。一个新环境建议先配置全局默认值，再给关键账户单独覆盖，最后用搜索接口验证数据库中确实存在目标邮件。

1
确认账户可访问
完成 OAuth2 或 IMAP 接入后，先读取 GET /api/accounts/{id}/mailboxes，确认 provider 文件夹能正常返回。
2
设置全局默认
全局配置控制默认是否自动同步、默认间隔、默认文件夹、worker 数和每轮邮件数量。
3
给账户覆盖配置
关键账户可以更短间隔、更多文件夹；大邮箱账户可以限制为 INBOX 并降低每轮压力。
4
手动同步并验证搜索
调用 POST /api/accounts/{id}/sync-now 后，使用 GET /api/emails/search 检查目标邮件是否已入库。
curl -X PUT "$BASE_URL/api/sync/global-config" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "default_enable_sync": true,
    "default_sync_interval": 300,
    "default_sync_folders": ["INBOX"],
    "max_sync_workers": 10,
    "max_emails_per_sync": 100
  }'

同步配置层级

全局同步配置

由 GlobalSyncConfig 表示，包含默认启用、默认间隔、默认文件夹、最大 worker、每次同步邮件数。

GET/api/sync/global-config读取
PUT/api/sync/global-config更新

账户同步配置

由 EmailAccountSyncConfig 表示，按账户覆盖全局默认值，并记录同步状态与错误恢复字段。

GET/api/accounts/{id}/sync-config读取
PUT/api/accounts/{id}/sync-config更新

临时同步配置

由 TemporarySyncConfig 表示，带过期时间，适合取件时短时间高频拉取。

POST/api/accounts/{id}/sync-config/temporary创建

账户同步配置示例

curl -X PUT "$BASE_URL/api/accounts/12/sync-config" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "enable_auto_sync": true,
    "sync_interval": 120,
    "sync_folders": ["INBOX", "Updates"]
  }'

curl -X POST "$BASE_URL/api/accounts/12/sync-config/temporary" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "sync_interval": 5,
    "sync_folders": ["INBOX"],
    "duration_minutes": 5
  }'
状态字段来源含义处理建议
sync_statusEmailAccountSyncConfigidle、syncing、error。error 时优先查看 last_sync_error 和账户认证状态。
last_sync_time账户配置最近一次同步开始时间。长时间不更新说明自动同步未调度或账户被禁用。
last_sync_end_time账户配置最近一次同步结束时间。开始时间有、结束时间无，说明可能仍在执行或异常中断。
last_history_idGmail 增量游标用于 Gmail 增量同步。不要随意清理；重建全量同步前再删除同步记录。

邮件读取与搜索

Mailman 的搜索接口读取数据库中的邮件，不直接请求 provider。因此“同步”是阅读邮件、触发器和取件的基础。

账户内读取

POST/api/account-emails/fetch/{id}抓取并保存邮件
GET/api/account-emails/list/{id}账户邮件列表
GET/api/account-emails/folders文件夹汇总
POST/api/account-emails/extract/{id}账户内提取

全局读取

GET/api/account-emails/list/all所有邮件
GET/api/emails/search条件搜索
GET/api/emails/{id}邮件详情
POST/api/emails/{id}/sync-attachments同步附件
curl "$BASE_URL/api/emails/search?account_id=12&to_query=user@example.com&subject_query=code&limit=20" \
  -H "Authorization: Bearer $TOKEN"
curl "$BASE_URL/api/emails/search?from_query=github.com&start_date=2026-01-01T00:00:00Z&limit=50" \
  -H "Authorization: Bearer $TOKEN"
curl "$BASE_URL/api/account-emails/list/12?mailbox=INBOX&limit=50&offset=0" \
  -H "Authorization: Bearer $TOKEN"

邮件搜索字段

GET /api/emails/search 和 GET /api/account-emails/list/{id} 都使用高级搜索参数。字段来自 backend/internal/api/email_query_handlers.go 的 Swagger 注释和解析逻辑。

参数说明示例
account_id仅全局搜索接口支持，用于限定账户。account_id=12
limit / offset分页参数，limit 默认 50，最大 100。limit=20&offset=0
sort_by排序：date_desc、date_asc、subject_asc、subject_desc。sort_by=date_desc
start_date / end_dateRFC3339 时间范围。start_date=2026-05-31T10:00:00Z
from_query / to_query / cc_query发件人、收件人、抄送人模糊匹配。to_query=user@example.com
subject_query主题模糊匹配。subject_query=verification
body_query / html_query纯文本正文或 HTML 正文模糊匹配。body_query=reset password
keyword跨文本字段全局搜索。keyword=invoice
mailbox按 provider 文件夹过滤。mailbox=INBOX
 
curl "$BASE_URL/api/emails/search?account_id=12&to_query=login@example.com&subject_query=code&start_date=2026-05-31T10:00:00Z&limit=10&sort_by=date_desc" \
  -H "Authorization: Bearer $TOKEN"

实践建议

新账户接入后，先手动同步一次，再开启自动同步。这样能把 OAuth2、provider 权限、代理、文件夹配置问题尽早暴露出来。

验证码账户

同步间隔可以稍短，但建议通过 /api/pickup/poll 触发临时同步，而不是长期全局高频同步。

大邮箱账户

限制同步文件夹和每次同步数量，保留增量游标，避免频繁清理同步记录。

多账户运营

使用批量同步配置、账户标签和代理池分组，把账户按业务、地区、风险分层。

排查漏信

检查 provider 文件夹、同步记录、搜索条件、转发落件地址和账户错误状态。

同步故障排查路径

同步接口报错

  1. 调用 GET /api/accounts/{id} 确认账户存在且属于当前组织。
  2. 调用 GET /api/accounts/{id}/mailboxes 验证 provider 凭据和代理链路。
  3. 查看 GET /api/accounts/{id}/sync-config 的 last_sync_error。
  4. 若 OAuth2 过期，回到账户 OAuth2 重连，不要只重试同步。

搜索不到邮件

  1. 先放宽搜索，只保留 account_id 和 limit。
  2. 确认 start_date 没有晚于邮件时间。
  3. 检查目标邮件实际所在文件夹是否在 sync_folders 中。
  4. 转发场景同时搜索落件地址和原始地址，避免只看 to_query。
最小闭环：mailboxes 能返回、sync-now 能成功、emails/search 能搜到、pickup/poll 能提取。四步都通过后，再配置触发器或业务集成。
