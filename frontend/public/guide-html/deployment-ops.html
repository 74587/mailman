生产上线前检查

先把运行环境、域名、数据库、OAuth2 回调、密钥和健康检查固定下来，再开始导入真实账户。这样后续同步、取件和触发器才有稳定基础。

检查项要求为什么重要
外部域名生产环境使用 HTTPS 域名访问后端。OAuth2 回调、Webhook、浏览器安全策略都依赖稳定域名。
数据库小规模可 SQLite，生产推荐 PostgreSQL。多账户同步、触发器日志、业务资产更适合独立数据库。
加密密钥固定设置 ENCRYPTION_KEY，升级和迁移不能丢。OAuth2 token、AI key 等敏感字段需要可持续解密。
OAuth2 回调Gmail/Outlook 控制台回调与 /api/oauth2/callback/{provider} 完全一致。一个字符不一致都会导致授权失败。
备份任务至少每天备份数据库和持久化数据。邮件索引、模板、触发器、业务账户都在数据库中。
健康检查GET /api/health 接入监控。升级和故障时先判断服务本身是否存活。

Docker All-in-One

docker run -d \
  --name mailman \
  -p 8080:8080 \
  -v mailman_data:/app/data \
  -e DB_DRIVER=sqlite \
  -e DB_NAME=/app/data/mailman.db \
  --restart unless-stopped \
  ghcr.io/seongminhwan/mailman-all:latest
All-in-One 镜像工作目录为 /app/backend，前端静态文件位于 /app/frontend/out。HTML 接入手册来自前端 public 构建产物，路径为 /guide-html/index.html。

Docker Compose 生产部署

cat > .env << 'EOF'
POSTGRES_DB=mailman
POSTGRES_USER=mailman
POSTGRES_PASSWORD=change-me
MAILMAN_PORT=8080
EOF

docker compose up -d
docker compose logs -f mailman

当前 docker-compose.yml 使用 PostgreSQL 16 Alpine，并将应用数据挂载到 mailman_data。

POSTGRES_PASSWORD、ENCRYPTION_KEY、OAuth2 client secret 和 AI key 不要提交到仓库。建议使用服务器上的 .env、密钥管理服务或部署平台 Secret。

关键环境变量

变量说明默认/示例
SERVER_HOST后端监听地址0.0.0.0
SERVER_PORT后端监听端口8080
DB_DRIVER数据库驱动sqlite、postgres、mysql
DB_HOST / DB_PORT数据库地址PostgreSQL 默认 5432
DB_USER / DB_PASSWORD数据库认证生产环境必须设置强密码
DB_NAME数据库名或 SQLite 文件路径/app/data/mailman.db
ENCRYPTION_KEY敏感数据加密密钥建议生产环境固定设置
GMAIL_REDIRECT_URIGmail OAuth2 回调覆盖值https://domain/api/oauth2/callback/gmail
OUTLOOK_REDIRECT_URIOutlook OAuth2 回调覆盖值https://domain/api/oauth2/callback/outlook

AI 和 OAuth2 client 凭据主要通过 Web 界面管理，不建议硬编码到镜像或前端代码中。

源码开发模式

开发时前后端可以分开启动：后端提供 API，前端 Next.js 通过 NEXT_PUBLIC_API_URL 指向后端。HTML 接入手册位于前端 public/guide-html，修改后浏览器刷新即可看到。

后端

cd backend
go run ./cmd/server

启动后先访问 http://127.0.0.1:8080/api/health。

前端

cd frontend
npm install
npm run dev

默认访问 http://127.0.0.1:3000，本地端口冲突时 Next.js 会提示新端口。

如果前端页面能打开但 API 全部失败，先检查 NEXT_PUBLIC_API_URL、浏览器 Network 中的实际请求地址，以及后端 CORS/反向代理配置。

备份、升级与回滚

PostgreSQL 备份

docker compose exec postgres pg_dump -U mailman mailman > mailman-$(date +%F).sql

恢复前先停止应用写入，再导入到新库并验证 /api/health。

SQLite 备份

docker cp mailman:/app/data/mailman.db ./mailman-$(date +%F).db

SQLite 适合小规模部署，复制前最好短暂停止容器或使用数据库在线备份能力。

升级流程

  1. 备份数据库、持久化目录和 .env。
  2. 拉取新镜像或部署新版本。
  3. 启动后检查 /api/health、登录、账户列表。
  4. 抽样验证同步、取件、触发器、AI 和代理池。

回滚流程

  1. 保留上一版本镜像标签或构建产物。
  2. 如数据库迁移不可逆，使用升级前备份恢复。
  3. 恢复后重新测试 OAuth2、同步和触发器。
  4. 记录失败版本、错误日志和回滚时间。

生产运维建议

备份

  • SQLite：备份 /app/data/mailman.db 和附件数据。
  • PostgreSQL：使用 pg_dump 定期备份。
  • 升级前先备份数据库和环境变量。

升级

  • 拉取新镜像后重启容器。
  • 观察 /api/health 和应用日志。
  • 验证 OAuth2、同步、取件、触发器核心路径。

监控

  • 健康检查：GET /api/health。
  • 同步状态：/api/sync/account-status。
  • 触发器日志：/api/triggers/logs/stats。
  • 活动日志：/api/activities/stats。

安全

  • 生产环境使用 HTTPS 和可信域名。
  • OAuth2 redirect URI 必须与云平台配置完全一致。
  • 为团队成员配置最小权限角色。
  • 定期轮换 OAuth2 client secret 和 AI key。

升级后冒烟测试

能力验证接口通过标准
服务健康GET /api/health返回成功且响应时间稳定。
登录认证POST /api/auth/login、GET /api/auth/me能获取 Token 并读取当前用户。
账户GET /api/accounts/paginated分页列表正常，权限过滤正确。
同步POST /api/accounts/{id}/sync-now同步成功或返回可解释的 provider 错误。
取件POST /api/pickup/poll候选邮件和提取结果符合预期。
触发器POST /api/v2/triggers/test-complete条件和动作测试通过。
