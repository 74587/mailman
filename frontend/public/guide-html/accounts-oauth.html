打开 OAuth2 配置

0 到 1 接入 Gmail 或 Outlook

最推荐的生产路径是：先创建 OAuth2 全局配置，再启动授权会话，授权成功后调用一站式入库接口。这个接口可以在一次请求里完成账户创建、验证、初始同步和自动同步配置。

1
在 provider 控制台创建 OAuth 应用
Gmail 需要 Gmail API 和用户信息 scope；Outlook 需要 IMAP/POP/SMTP 相关 scope 和 offline_access。回调地址要和 Mailman 的 redirect_uri 完全一致。
2
在 Mailman 添加 OAuth2 全局配置
菜单：系统配置 → OAuth2 配置。保存 provider_type、client_id、client_secret、redirect_uri、scopes。
3
启动授权会话
调用 POST /api/oauth2/session/start/{provider}?config_id=1，拿到 authUrl 和 state。用户打开授权链接完成授权。
4
轮询授权结果
调用 GET /api/oauth2/session/poll/{state}。成功时会返回邮箱地址、token 数据和 provider 配置 ID。
5
账户入库并验证
调用 POST /api/accounts/oauth2/onboard。建议开启 verify、run_initial_sync、create_sync_config。
6
确认可读、可同步、可触发
看账户 isVerified、同步时间、错误状态和邮件列表。只有同步到数据库的邮件才能被搜索、取件和触发器处理。

账户模型关系

邮件账户由 EmailAccount 表示，OAuth2 provider 凭据由 OAuth2GlobalConfig 表示。账户还可以关联邮件服务商、代理池、业务账户、标签和同步配置。

对象关键字段说明
OAuth2GlobalConfigprovider_type、client_id、client_secret、redirect_uri、scopes、is_enabled、is_default一套 provider 凭据。一个 provider 可以有多套配置。
EmailAccountemailAddress、authType、oauth2ProviderId、customSettings、forwardedAddresses、proxyMode实际邮箱账户。OAuth2 token 存在 customSettings 中。
EmailAccountSyncConfigenable_auto_sync、sync_interval、sync_folders账户级同步配置，可在 OAuth2 入库时一起创建。

OAuth2 接入方式

curl -X POST "$BASE_URL/api/oauth2/global-config" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Gmail production app",
    "provider_type": "gmail",
    "client_id": "xxxxx.apps.googleusercontent.com",
    "client_secret": "GOCSPX-xxxxx",
    "redirect_uri": "https://mailman.example.com/api/oauth2/callback/gmail",
    "scopes": [
      "https://mail.google.com/",
      "https://www.googleapis.com/auth/userinfo.email",
      "https://www.googleapis.com/auth/userinfo.profile"
    ],
    "is_enabled": true,
    "is_default": true
  }'
Outlook 常用 scope：https://outlook.office.com/IMAP.AccessAsUser.All、https://outlook.office.com/POP.AccessAsUser.All、https://outlook.office.com/SMTP.Send、offline_access。
curl -X POST "$BASE_URL/api/oauth2/session/start/gmail?config_id=1" \
  -H "Authorization: Bearer $TOKEN"

返回中重点看 authUrl、state、expiresAt。用户授权完成后，provider 回调 /api/oauth2/callback/{provider}，Mailman 会把会话状态更新为 success、failed、expired 或 cancelled。

curl "$BASE_URL/api/oauth2/session/poll/$STATE" \
  -H "Authorization: Bearer $TOKEN"
curl -X POST "$BASE_URL/api/accounts/oauth2/onboard" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "emailAddress": "user@gmail.com",
    "authType": "oauth2",
    "mailProviderId": 1,
    "oauth2ProviderId": 1,
    "forwardedAddresses": ["*@example.com", "alerts@example.org"],
    "customSettings": {
      "access_token": "ya29...",
      "refresh_token": "1//...",
      "expires_at": "2026-05-31T11:00:00Z",
      "provider": "gmail"
    },
    "proxyMode": "manual",
    "proxy": "socks5://127.0.0.1:1080",
    "verify": true,
    "run_initial_sync": true,
    "create_sync_config": true,
    "update_existing": true,
    "initial_sync": {
      "mailbox": "INBOX",
      "limit": 50
    },
    "sync_config": {
      "enable_auto_sync": true,
      "sync_interval": 300,
      "sync_folders": ["INBOX"]
    }
  }'

后端要求 authType 为空或 oauth2，并要求 customSettings.access_token 存在。若 oauth2ProviderId 为空，会尝试从 customSettings 推断。

手动模式适合无法让用户在当前浏览器回跳 Mailman 的场景。Gmail 的手动回调地址为 http://localhost，Yahoo/AOL 为 https://127.0.0.1，具体由 provider metadata 决定。

POST/api/oauth2/session/manual/start/{provider}创建手动授权会话
POST/api/oauth2/session/manual/exchange/{state}提交 callback URL 或 code
POST/api/oauth2/exchange-token直接交换授权码
POST/api/oauth2/refresh-token刷新 access token

临时使用 Thunderbird OAuth2 凭据验证

高风险警告：不要在生产环境使用其他人的 OAuth2 客户端凭据。 使用第三方客户端凭据是不安全的，也是不允许的。下面内容只用于在你自己的应用凭据尚未审批下来前，快速验证 Mailman 的 OAuth2 授权、回调、入库和同步链路。生产环境务必使用你自己在 Google、Microsoft 或对应邮箱服务商控制台注册的凭据。

Thunderbird 的开源代码中维护了一组 provider 元数据，可在临时验证时作为参考。源码里的 kHostnames 会把邮箱主机映射到 issuer 和 scope，kIssuers 中包含 clientId、可选 clientSecret、授权端点、token 端点和 PKCE 配置。Thunderbird 源码本身也明确提醒不要复制这些值作为自己的应用凭据。

从 Thunderbird 源码读取字段

  1. 打开 OAuth2Providers.sys.mjs。
  2. 在 kHostnames 中按邮箱服务找到 issuer，例如 Gmail 对应 accounts.google.com，Outlook/Office365 对应 login.microsoftonline.com。
  3. 到 kIssuers 中找到同名 issuer，把 clientId 填入 Mailman 的 client_id；如果有 clientSecret，填入 client_secret，没有则留空。
  4. Mailman 已内置常见 provider 的授权端点和 token 端点；这里只需要确认 provider_type、client_id、client_secret、redirect_uri 和 scopes。

本地回调代理是必需的

使用第三方客户端凭据时，授权回调通常会打到本机 loopback 地址。如果不在本地启动代理，部署在 mailman.easycat.io 的 Mailman 无法接收到授权回调，也就无法保存授权会话。

# 在 mailman 仓库根目录执行
make proxy PROXY_PORT=18080 PROXY_TARGET=https://mailman.easycat.io PROXY_BACKGROUND=true

这个命令会在本地监听 18080，并把收到的 OAuth2 回调请求转发到 https://mailman.easycat.io。完成临时验证后应停止代理，并删除这套临时 OAuth2 配置。

在 Mailman 中新增临时 OAuth2 Provider

进入 系统配置 → OAuth2 配置，新增一套临时配置。provider_type 必须使用 Mailman 支持的类型，例如 gmail、outlook、yahoo、aol、fastmail、yandex、mailru 或 comcast。redirect_uri 使用本地代理地址，并保留 Mailman 的回调路径：

http://localhost:18080/api/oauth2/callback/{provider}
Mailman 字段临时填写方式说明
nameGmail Thunderbird quick verify名称要明确标记为临时验证配置。
provider_typegmail 或 outlook 等选择与邮箱账户匹配的 Mailman provider 类型。
client_idThunderbird kIssuers 对应 issuer 的 clientId只用于临时验证，不要设为生产默认配置。
client_secret对应 issuer 的 clientSecret；若源码未提供则留空Outlook 这类 public client 通常没有 secret。
redirect_urihttp://localhost:18080/api/oauth2/callback/gmail把 gmail 替换成实际 provider，例如 outlook。
scopes优先使用 Mailman 默认 scopesGmail 常用 https://mail.google.com/；Outlook 常用 IMAP、POP、SMTP 和 offline_access。

1
启动本地代理
先执行 make proxy PROXY_PORT=18080 PROXY_TARGET=https://mailman.easycat.io PROXY_BACKGROUND=true，确认本机端口未被占用。

密码、Token 与自定义 IMAP/SMTP

不是所有邮箱都走 OAuth2。iCloud、QQ、163、企业自建邮箱通常使用应用专用密码、授权码或 IMAP/SMTP token。

创建密码账户

curl -X POST "$BASE_URL/api/accounts" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "emailAddress": "robot@example.com",
    "authType": "password",
    "password": "app-specific-password",
    "mailProviderId": 3,
    "forwardedAddresses": ["*@example.com"],
    "proxyMode": "manual",
    "proxy": "",
    "note": "业务验证码落件账户",
    "noteFormat": "markdown",
    "customSettings": {}
  }'

创建 Token 账户

curl -X POST "$BASE_URL/api/accounts" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "emailAddress": "robot@example.com",
    "authType": "token",
    "token": "imap-or-provider-token",
    "mailProviderId": 3,
    "isDomainMail": true,
    "domain": "example.com",
    "forwardedAddresses": ["robot@example.com", "*@example.com"]
  }'
前端类型中还有 app_password 命名，但后端模型当前认证枚举是 password、token、oauth2。外部 API 接入时以后端枚举为准。

账户关键字段

字段用途怎么填注意事项
emailAddress邮箱地址完整邮箱，例如 user@gmail.com。后端按邮箱唯一索引保存。
authType认证方式password、token、oauth2。OAuth2 入库接口会校验必须为 oauth2。
mailProviderId邮件服务商从 GET /api/providers 获取。自定义 provider 可选，但接入同步时建议明确配置。
oauth2ProviderIdOAuth2 凭据配置对应 OAuth2GlobalConfig.id。多套 Gmail/Outlook 配置时必须指定。
customSettings扩展设置OAuth2 token、expires_at、provider 等。access_token 是 OAuth2 入库必填。
forwardedAddresses转发落件地址支持精确邮箱和 *@domain.com。取件和业务映射常依赖这个字段。
proxyMode账户代理模式manual、selected、auto。配合 proxy、proxyId、fallback 字段使用。
isVerified验证状态由验证接口更新。只代表最近一次连接验证结果，不代表后续同步永远成功。
errorStatus错误状态normal、oauth_expired、auth_revoked、api_disabled、network_error、quota_exceeded、server_error。同步器会根据错误类型更新。

错误状态与恢复动作

oauth_expired

access token 过期且 refresh 失败。先调用刷新接口，失败再重新授权。

auth_revoked

用户撤销授权或 refresh token 失效。重新启动授权会话并更新账户。

api_disabled

Gmail API 或 Microsoft API 未启用，或者 scope 不足。回 provider 控制台修正。

network_error

网络或代理失败。检查账户代理、代理池状态、防火墙和服务器出口。

quota_exceeded

provider 配额受限。降低同步频率、减少文件夹或拆分 OAuth2 配置。

server_error

provider 或后端内部错误。结合后端日志和同步记录定位。

验证通过后，OAuth2 入库流程会把账户错误状态重置为 normal，并清空错误消息、错误时间和错误计数。
