Business Account Automation

从领取邮箱到回写业务账户的注册自动化

本教程把邮箱账户、业务模块、取件、验证码提取和业务资料回写串成一条可生产使用的链路。你会看到如何原子领取邮箱，如何选择主邮箱、域名邮箱、别名邮箱或转发地址，以及如何在注册成功后把外部平台账号写回 Mailman。

目标流程

这条流程适合外部注册机器人、账号开通任务、批量 onboarding、站点账号资产沉淀等场景。Mailman 负责邮箱资源的分配、验证码邮件取件和业务资料持久化；外部系统负责真正访问目标站点并提交注册表单。

1
领取一个可注册邮箱
调用 POST /api/business-modules/{id}/email-accounts/claim，Mailman 会创建一个 pending 业务账户作为锁，返回 emailAccount.id、实际注册邮箱、businessAccountId 和 claimToken。
2
预热取件窗口
记录 since 时间，并调用一次 POST /api/pickup/poll。它会为目标邮箱注册临时同步覆盖，后续几分钟内以更高频率拉取新邮件。
3
触发目标站点注册
外部系统把 recipient.emailAddress 填到目标站点注册表单里，目标站点发出验证码邮件。
4
轮询验证码
用 claim 返回的 pickup.account_id 和 pickup.to_query 反复调用 /api/pickup/poll，配合 simple_extract 或 template_id 提取验证码。
5
完成注册并回写
外部系统提交验证码成功后，调用 POST /api/business-accounts/{id}/complete-registration，写入 username、password、2FA、恢复码、外部用户 ID 等资料。
6
失败时释放
如果注册失败、验证码超时或任务取消，调用 release-registration-claim 释放占用；如果流程很长，调用 renew-registration-claim 延长锁。

准备工作

先确认 Mailman 里已经有业务模块和可收信邮箱。claim 接口只会选择已验证、错误状态正常、属于当前组织的邮箱账户。

1. 创建业务模块

业务模块代表目标平台，例如 GitHub、Shopify、Stripe。claim 接口路径里的 {id} 就是业务模块 ID。

curl -X POST "$BASE_URL/api/business-modules" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "GitHub",
    "website": "https://github.com",
    "loginUrl": "https://github.com/login",
    "description": "GitHub 账号注册自动化",
    "statusOptions": {
      "pending": "注册中",
      "active": "可用",
      "disabled": "停用",
      "archived": "归档"
    }
  }'

2. 准备邮箱池

邮箱账户必须 isVerified=true 且 errorStatus 为空或 normal。域名邮箱需要维护 isDomainMail 和 domain；转发场景需要维护 forwardedAddresses。

POST/api/accounts/oauth2/onboardOAuth2 开通账户
POST/api/accounts密码或 token 账户
POST/api/accounts/verify验证账户可用性
PUT/api/accounts/{id}/forwarded-addresses维护转发地址
业务自动化接口使用 Bearer Token，与其他受保护 API 一样走当前组织上下文。生产任务建议每个 worker 使用独立 claimedBy，便于审计和排查。

第一步：领取并锁定邮箱

POST /api/business-modules/{id}/email-accounts/claim 会在事务里选择一个邮箱账户，并创建一个 pending 业务账户作为注册锁。锁的唯一性是 orgId + moduleId + registrationEmail，因此同一个业务模块里同一个注册邮箱不会被两个任务同时领取。

POST/api/business-modules/{id}/email-accounts/claim领取邮箱

最小请求

{
  "ttlSeconds": 600,
  "claimedBy": "register-worker-01"
}

请求字段

字段类型说明建议
ttlSecondsnumber领取有效期。默认 600 秒，最小 60 秒，最大 3600 秒。验证码注册常用 600-900；长流程用 renew 续期。
claimedBystring占用者标识，会写入 pending 业务账户。填写 worker 名、任务 ID 或批次号。
accountIdnumber指定物理邮箱账户 ID。精确调度时使用。
emailAddressstring指定注册邮箱。可以是主邮箱、Gmail plus 地址、域名别名或转发地址；后端会解析到对应邮箱账户。重试固定邮箱时使用。
emailModestringauto、primary、domain、alias、forwarded。不传默认为 auto。
useDomainMailboolean是否要求域名邮箱。域名注册池传 true。
domainstring限定域名，例如 example.com。和 emailMode=domain 或 aliasType=domain_local_part 一起用。
useAliasbooleanauto 模式下优先使用别名。Gmail plus 或域名 catch-all 推荐 true。
aliasTypestringgmail_plus、domain_local_part、forwarded。精确声明别名生成方式。
aliasLocalPartstring别名前缀。后端会清理非法字符并限制长度。可用外部任务 ID，便于追踪。
tagIdsnumber[]只从带有这些标签的邮箱账户中选择。按地区、用途、风险分池。
tagFilterModestringor 或 and。默认 or。严格分池用 and。
providerIdnumber限定邮箱 provider。只使用 Gmail 或自建 IMAP 时传。
authTypesstring[]限定认证方式，如 oauth2、password、token。避免选择不适合自动同步的账户。
proxyModestring限定邮箱账户代理模式。需要和目标站点地区一致时传。
businessAccountobject创建 pending 业务账户时预填资料。可写入 displayName、username、description、note、tags、customFields、extraData。

邮箱选择模式

claim 可以自动从邮箱池里找，也可以精确指定一个邮箱。下面几个 tab 覆盖最常见的注册策略。

使用邮箱账户自己的 emailAddress 注册。适合“一邮箱一平台账号”的简单模式。

{
  "emailMode": "primary",
  "ttlSeconds": 600,
  "tagIds": [3, 8],
  "tagFilterMode": "and",
  "businessAccount": {
    "displayName": "GitHub registration",
    "customFields": { "batch": "2026-05-31-us" }
  }
}

从域名邮箱或 catch-all 账户生成 localPart@domain。后端要求邮箱账户 isDomainMail=true 且 domain 匹配。

{
  "emailMode": "domain",
  "domain": "example.com",
  "aliasLocalPart": "github-task-3921",
  "claimedBy": "register-worker-01"
}

对 Gmail 或 Googlemail 主邮箱生成 plus 地址，例如 user+github3921@gmail.com。后端会限定 @gmail.com 或 @googlemail.com。

{
  "emailMode": "alias",
  "aliasType": "gmail_plus",
  "aliasLocalPart": "github3921",
  "authTypes": ["oauth2"]
}

使用邮箱账户维护的 forwardedAddresses。如果地址里有 *@domain，后端会基于 aliasLocalPart 生成具体收件地址。

{
  "emailMode": "forwarded",
  "domain": "inbound.example.net",
  "aliasLocalPart": "shopify-20260531-0001"
}

指定 accountId 或 emailAddress。传 emailAddress 时，后端会通过主邮箱、别名或转发地址解析到物理邮箱账户。

{
  "accountId": 12,
  "emailAddress": "github-a1b2@example.com",
  "ttlSeconds": 300
}

第二步：启动监听并获取验证码

/api/pickup/poll 是取件接口。它不会一直阻塞到验证码出现，而是注册临时同步覆盖、立即同步一次、搜索邮件并执行提取。业务侧应在 claim 后记录 since，先调用一次预热，然后触发外部注册，再每 3-5 秒轮询直到取到验证码或超时。

POST/api/pickup/poll取件轮询
{
  "account_id": 12,
  "to_query": "github-a1b2@example.com",
  "since": "2026-05-31T08:30:00Z",
  "keep_alive_seconds": 120,
  "sync_interval": 5,
  "limit": 10,
  "simple_extract": {
    "field": "body",
    "type": "regex",
    "pattern": "\\b\\d{6}\\b",
    "match_mode": "first"
  }
}
字段来源说明
account_idclaim.pickup.account_id物理邮箱账户 ID。推荐直接使用 claim 响应值。
to_queryclaim.pickup.to_query实际收件地址。对转发和别名场景尤其关键。
since业务侧生成触发注册前记录当前时间，避免提取旧邮件里的验证码。
keep_alive_seconds业务侧配置临时同步覆盖有效期。轮询期间可以持续传同一个值。
sync_interval业务侧配置取件期间拉信间隔，默认 5 秒。
template_id取件模板生产推荐。适合不同平台维护不同模板。
simple_extract请求内声明只提验证码时足够简单。
inline_actions请求内声明需要表达式、动作链、输出配置但不想预建模板时使用。

成功响应怎么看

{
  "success": true,
  "account_id": 12,
  "requested_account_id": 12,
  "resolved_by": "to_query",
  "new_count": 1,
  "extractions": [
    {
      "email_id": 9901,
      "success": true,
      "status": "success",
      "extracted_value": "123456"
    }
  ],
  "sync_active": true,
  "sync_expires_at": "2026-05-31T08:32:00Z"
}
如果 extractions 为空，通常表示还没收到邮件；如果 status=no_match，表示邮件到了但模板或正则没有匹配。先用简单正则打通，再沉淀为取件模板，是最稳的落地方式。

第三步：完成、续期与释放

claim 创建的 pending 业务账户有三种后续动作：注册成功后 complete，流程延长时 renew，失败或取消时 release。三个接口都要求 claimToken，防止其他任务误操作。

完成注册

POST/api/business-accounts/{id}/complete-registration回写资料

默认把状态置为 active，清空 claimExpiresAt，保留 registrationEmail，并把 extraData.registrationState 置为 completed。

续期占用

POST/api/business-accounts/{id}/renew-registration-claim延长 TTL

只允许 pending 且未过期的 claim 续期。TTL 规则同 claim：默认 600，最小 60，最大 3600 秒。

释放占用

POST/api/business-accounts/{id}/release-registration-claim释放邮箱

不能释放已完成的 active 账户。默认归档 pending 账户并清空 registrationEmail；也可设置 deletePendingAccount=true 删除草稿。

complete 请求

{
  "claimToken": "claim_3c6d9a9f1d0b6f8c2a7e4d10b0cc64a9f2d3",
  "username": "octo-login",
  "password": "generated-password",
  "totpSecret": "BASE32TOTPSECRET",
  "recoveryEmail": "recovery@example.com",
  "recoveryCodes": ["code-1", "code-2"],
  "status": "active",
  "customFields": {
    "externalUserId": "ghu_123456",
    "plan": "free"
  },
  "extraData": {
    "registrationJobId": "job-20260531-0001"

renew 与 release 请求

{
  "claimToken": "claim_3c6d9a9f1d0b6f8c2a7e4d10b0cc64a9f2d3",
  "ttlSeconds": 900,
  "message": "remote site is still processing"
}
{
  "claimToken": "claim_3c6d9a9f1d0b6f8c2a7e4d10b0cc64a9f2d3",
  "reason": "captcha_timeout",
  "message": "no verification email after 180 seconds",
  "deletePendingAccount": false,
  "exclusion": {
    "type": "cooldown",
    "scope": "module",
    "target": "email_account",
    "durationSeconds": 1800
  }
}

release 可选写入邮箱排除规则。type=cooldown 会按 durationSeconds 临时排除；type=blacklist 没有过期时间。scope=module 只影响当前业务模块，scope=global 影响当前组织所有业务模块；target 可选 email_account、registration_email 或 both。

{
  "claimToken": "claim_3c6d9a9f1d0b6f8c2a7e4d10b0cc64a9f2d3",
  "reason": "already_registered",
  "exclusions": [
    {
      "type": "blacklist",
      "scope": "module",
      "target": "registration_email"
    }
  ]
}
如果 worker 崩溃没有 release，claim 会在过期后被下一次 claim 自动清理并释放注册邮箱。仍然建议业务侧在失败路径主动 release，因为这样可以留下明确的失败原因。

完整代码示例

下面三段示例都遵循同一条链路：claim、预热 pickup、触发外部注册、轮询验证码、提交验证码、complete；任何异常都会 release。

const API_BASE = process.env.MAILMAN_API_BASE || 'http://127.0.0.1:3001/api'
const TOKEN = process.env.MAILMAN_TOKEN
const MODULE_ID = process.env.MAILMAN_MODULE_ID || '7'

const sleep = ms => new Promise(resolve => setTimeout(resolve, ms))

async function api(path, options = {}) {
  const response = await fetch(`${API_BASE}${path}`, {
    method: options.method || 'GET',
    headers: {
      Authorization: `Bearer ${TOKEN}`,
      'Content-Type': 'application/json',
      ...(options.headers || {})
    },
    body: options.body ? JSON.stringify(options.body) : undefined
  })
  const text = await response.text()
  const data = text ? JSON.parse(text) : null
  if (!response.ok) {
    throw new Error(`${response.status} ${path}: ${text}`)
  }
  return data
}

async function triggerRemoteRegistration(email) {
  // 在这里调用目标站点注册接口或浏览器自动化脚本，把 email 填入注册表单。
  return { username: email.split('@')[0], password: crypto.randomUUID() }
}

async function submitRemoteCode(code) {
  // 在这里把 Mailman 提取到的验证码提交给目标站点。
  return { externalUserId: `remote-${code}`, plan: 'free' }
}

async function pickupCode(claim, since) {
  for (let attempt = 0; attempt < 36; attempt += 1) {
    const result = await api('/pickup/poll', {
      method: 'POST',
      body: {
        account_id: claim.pickup.account_id,
        to_query: claim.pickup.to_query,
        since,
        keep_alive_seconds: 180,
        sync_interval: 5,
        limit: 10,
        simple_extract: {
          field: 'body',
          type: 'regex',
          pattern: '\\\\b\\\\d{6}\\\\b',
          match_mode: 'first'
        }
      }
    })
    const item = (result.extractions || []).find(x => x.success && x.extracted_value)
    if (item) return String(item.extracted_value)
    await sleep(5000)
  }
  throw new Error('verification code timeout')
}

async function main() {
  const claim = await api(`/business-modules/${MODULE_ID}/email-accounts/claim`, {
    method: 'POST',
    body: {
      ttlSeconds: 900,
      claimedBy: 'node-register-worker-01',
      emailMode: 'domain',
      domain: 'example.com',
      aliasLocalPart: `github-${Date.now()}`,
      businessAccount: {
        displayName: 'GitHub registration',
        customFields: { source: 'nodejs-demo' }
      }
    }
  })

  try {
    const since = new Date().toISOString()

    await api('/pickup/poll', {
      method: 'POST',
      body: {
        account_id: claim.pickup.account_id,
        to_query: claim.pickup.to_query,
        since,
        keep_alive_seconds: 180,
        sync_interval: 5,
        limit: 1
      }
    })

    const remoteDraft = await triggerRemoteRegistration(claim.recipient.emailAddress)
    const code = await pickupCode(claim, since)
    const remoteAccount = await submitRemoteCode(code)

    const completed = await api(`/business-accounts/${claim.businessAccountId}/complete-registration`, {
      method: 'POST',
      body: {
        claimToken: claim.claimToken,
        username: remoteDraft.username,
        password: remoteDraft.password,
        status: 'active',
        customFields: {
          externalUserId: remoteAccount.externalUserId,
          plan: remoteAccount.plan,
          registrationEmail: claim.recipient.emailAddress
        },
        extraData: { automation: 'nodejs-demo' },
        remoteCreatedAt: new Date().toISOString()
      }
    })
    console.log('completed business account', completed.id)
  } catch (error) {
    await api(`/business-accounts/${claim.businessAccountId}/release-registration-claim`, {
      method: 'POST',
      body: {
        claimToken: claim.claimToken,
        reason: 'automation_failed',
        message: String(error.message || error)
      }
    }).catch(() => {})
    throw error
  }
}

main().catch(error => {
  console.error(error)
  process.exitCode = 1
})
package main

import (
	"bytes"
	"encoding/json"
	"fmt"
	"net/http"
	"os"
	"time"
)

var apiBase = getenv("MAILMAN_API_BASE", "http://127.0.0.1:3001/api")
var token = os.Getenv("MAILMAN_TOKEN")
var moduleID = getenv("MAILMAN_MODULE_ID", "7")

func getenv(key, fallback string) string {
	if value := os.Getenv(key); value != "" {
		return value
	}
	return fallback
}

func api(method, path string, body any, out any) error {
	var payload *bytes.Reader
	if body == nil {
		payload = bytes.NewReader(nil)
	} else {
		raw, err := json.Marshal(body)
		if err != nil {
			return err
		}
		payload = bytes.NewReader(raw)
	}

	req, err := http.NewRequest(method, apiBase+path, payload)
	if err != nil {
		return err
	}
	req.Header.Set("Authorization", "Bearer "+token)
	req.Header.Set("Content-Type", "application/json")

	resp, err := http.DefaultClient.Do(req)
	if err != nil {
		return err
	}
	defer resp.Body.Close()

	if resp.StatusCode < 200 || resp.StatusCode >= 300 {
		return fmt.Errorf("%s %s returned %s", method, path, resp.Status)
	}
	if out != nil {
		return json.NewDecoder(resp.Body).Decode(out)
	}
	return nil
}

type Claim struct {
	BusinessAccountID uint   `json:"businessAccountId"`
	ClaimToken        string `json:"claimToken"`
	Recipient         struct {
		EmailAddress string `json:"emailAddress"`
	} `json:"recipient"`
	Pickup struct {
		AccountID uint   `json:"account_id"`
		ToQuery   string `json:"to_query"`
	} `json:"pickup"`
}

type PickupResult struct {
	Extractions []struct {
		Success        bool        `json:"success"`
		ExtractedValue interface{} `json:"extracted_value"`
	} `json:"extractions"`
}

func triggerRemoteRegistration(email string) (string, string, error) {
	// 在这里访问目标站点注册接口或浏览器自动化脚本。
	return "user-" + fmt.Sprint(time.Now().Unix()), "generated-password", nil
}

func submitRemoteCode(code string) (string, error) {
	// 在这里把验证码提交给目标站点。
	return "remote-" + code, nil
}

func pickupCode(claim Claim, since string) (string, error) {
	for attempt := 0; attempt < 36; attempt++ {
		var result PickupResult
		err := api("POST", "/pickup/poll", map[string]any{
			"account_id":         claim.Pickup.AccountID,
			"to_query":           claim.Pickup.ToQuery,
			"since":              since,
			"keep_alive_seconds": 180,
			"sync_interval":      5,
			"limit":              10,
			"simple_extract": map[string]any{
				"field":      "body",
				"type":       "regex",
				"pattern":    "\\b\\d{6}\\b",
				"match_mode": "first",
			},
		}, &result)
		if err != nil {
			return "", err
		}
		for _, item := range result.Extractions {
			if item.Success && item.ExtractedValue != nil {
				return fmt.Sprint(item.ExtractedValue), nil
			}
		}
		time.Sleep(5 * time.Second)
	}
	return "", fmt.Errorf("verification code timeout")
}

func main() {
	var claim Claim
	err := api("POST", "/business-modules/"+moduleID+"/email-accounts/claim", map[string]any{
		"ttlSeconds":     900,
		"claimedBy":      "go-register-worker-01",
		"emailMode":      "alias",
		"aliasType":      "gmail_plus",
		"aliasLocalPart": fmt.Sprintf("github-%d", time.Now().Unix()),
		"businessAccount": map[string]any{
			"displayName": "GitHub registration",
			"customFields": map[string]any{"source": "go-demo"},
		},
	}, &claim)
	if err != nil {
		panic(err)
	}

	release := func(reason string) {
		_ = api("POST", fmt.Sprintf("/business-accounts/%d/release-registration-claim", claim.BusinessAccountID), map[string]any{
			"claimToken": claim.ClaimToken,
			"reason":     reason,
		}, nil)
	}

	since := time.Now().UTC().Format(time.RFC3339)
	_ = api("POST", "/pickup/poll", map[string]any{
		"account_id":         claim.Pickup.AccountID,
		"to_query":           claim.Pickup.ToQuery,
		"since":              since,
		"keep_alive_seconds": 180,
		"sync_interval":      5,
		"limit":              1,
	}, nil)

	username, password, err := triggerRemoteRegistration(claim.Recipient.EmailAddress)
	if err != nil {
		release("remote_registration_failed")
		panic(err)
	}
	code, err := pickupCode(claim, since)
	if err != nil {
		release("captcha_timeout")
		panic(err)
	}
	externalUserID, err := submitRemoteCode(code)
	if err != nil {
		release("remote_code_submit_failed")
		panic(err)
	}

	var completed map[string]any
	err = api("POST", fmt.Sprintf("/business-accounts/%d/complete-registration", claim.BusinessAccountID), map[string]any{
		"claimToken": claim.ClaimToken,
		"username":   username,
		"password":   password,
		"status":     "active",
		"customFields": map[string]any{
			"externalUserId": externalUserID,
			"registrationEmail": claim.Recipient.EmailAddress,
		},
		"remoteCreatedAt": time.Now().UTC().Format(time.RFC3339),
	}, &completed)
	if err != nil {
		release("complete_registration_failed")
		panic(err)
	}
	fmt.Println("completed business account", completed["id"])
}
import os
import time
import uuid
from datetime import datetime, timezone

import requests

API_BASE = os.getenv("MAILMAN_API_BASE", "http://127.0.0.1:3001/api")
TOKEN = os.environ["MAILMAN_TOKEN"]
MODULE_ID = os.getenv("MAILMAN_MODULE_ID", "7")


def now_iso():
    return datetime.now(timezone.utc).isoformat().replace("+00:00", "Z")


def api(method, path, json_body=None):
    response = requests.request(
        method,
        API_BASE + path,
        headers={
            "Authorization": f"Bearer {TOKEN}",
            "Content-Type": "application/json",
        },
        json=json_body,
        timeout=30,
    )
    if not response.ok:
        raise RuntimeError(f"{response.status_code} {path}: {response.text}")
    return response.json() if response.text else None


def trigger_remote_registration(email):
    # 在这里调用目标站点注册接口或浏览器自动化脚本。
    return {
        "username": email.split("@")[0],
        "password": str(uuid.uuid4()),
    }


def submit_remote_code(code):
    # 在这里把验证码提交给目标站点。
    return {"externalUserId": f"remote-{code}", "plan": "free"}


def pickup_code(claim, since):
    for _ in range(36):
        result = api("POST", "/pickup/poll", {
            "account_id": claim["pickup"]["account_id"],
            "to_query": claim["pickup"]["to_query"],
            "since": since,
            "keep_alive_seconds": 180,
            "sync_interval": 5,
            "limit": 10,
            "simple_extract": {
                "field": "body",
                "type": "regex",
                "pattern": r"\b\d{6}\b",
                "match_mode": "first",
            },
        })
        for item in result.get("extractions", []):
            if item.get("success") and item.get("extracted_value"):
                return str(item["extracted_value"])
        time.sleep(5)
    raise TimeoutError("verification code timeout")


def release_claim(claim, reason, message=""):
    try:
        api("POST", f"/business-accounts/{claim['businessAccountId']}/release-registration-claim", {
            "claimToken": claim["claimToken"],
            "reason": reason,
            "message": message,
        })
    except Exception:
        pass


def main():
    claim = api("POST", f"/business-modules/{MODULE_ID}/email-accounts/claim", {

上线检查与常见错误

状态码

状态常见原因处理方式
201claim 成功保存 businessAccountId 和 claimToken。
404没有可用邮箱，或全部候选地址已被当前模块占用检查标签、域名、认证方式、错误状态，或等待 claim 过期。
403claimToken 错误不要混用不同任务的 token；不要从业务账户详情里取 token。
409claim 已过期、已完成、不可续期或不可释放按当前状态决定重新 claim、跳过或人工检查。
400请求体错误、since 时间格式错误since 必须是 RFC3339，例如 2026-05-31T08:30:00Z。

生产建议

  • 每个注册任务都记录 businessAccountId、claimToken、recipient.emailAddress 和外部任务 ID。
  • 用 since 排除旧验证码，且在触发目标站点注册前生成。
  • 长流程在 TTL 剩余一半时调用 renew，不要等到最后几秒。
  • 失败路径务必 release，并写入明确 reason。
  • 不同站点维护独立取件模板，减少正则误匹配。
  • 把域名、标签和 provider 作为邮箱池治理维度，避免所有任务抢同一批邮箱。
最小可用闭环是：claim 返回邮箱和业务账户 ID，pickup/poll 取到验证码，目标站点注册成功，complete-registration 把结果写回 Mailman。做到这四点，就已经完成了从邮箱资源到业务资产的自动化沉淀。
