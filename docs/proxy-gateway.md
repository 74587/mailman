# Proxy Gateway

Proxy Gateway 让 Mailman 作为一个独立的 HTTP / SOCKS5 代理入口，对外暴露监听端口，实际访问目标时再按代理池策略选择上游代理。代理访问账号独立于 Mailman 登录账号，适合给外部工具、浏览器、爬虫或自动化任务分配受控代理能力。

> 这篇文档是功能概要。完整的手把手配置和接入手册见：[代理池管理模块接入手册](./proxy-pool-management-guide.md)。

## 功能范围

- 支持 HTTP 代理、SOCKS5 代理、Mixed 混合监听。Mixed 会通过首字节自动识别 SOCKS5，其余按 HTTP 代理处理。
- 支持监听配置热加载。新增、更新、停用监听后可在页面点击“热加载”，不需要重启 Mailman 主服务。
- 支持独立网关用户：用户名、密码、备注、分组、标签、启用状态、过期时间，并可授权可使用的网关。
- 支持按账号配置代理选择策略：全部可用、按代理分组/标签过滤、显式临时代理池。
- 支持调度算法：随机、轮询、权重随机、最低延迟、优先复用最近成功代理。
- 支持 fallback 策略：中断、重试换代理、备用池、允许直连 fallback。
- 支持粘性策略：账号、客户端 IP、目标域名、客户端 IP + 目标域名。
- 支持网关级安全边界策略：来源 CIDR、目标 Host、目标端口、内网/回环/链路本地/多播/metadata 地址阻断。
- 支持网关级 DNS 策略：远端解析、本地解析、自定义 resolver、缓存 TTL、失败 TTL、多 IP 安全检查策略。
- 支持访问日志、配置审计日志、运行状态查看。
- 支持智能用户名路由：用户可在代理用户名后携带路由标志号，临时切换到被授权的路由策略。

## 菜单入口

代理相关能力已从“邮箱运营”菜单中独立出来，位于“代理池管理”菜单组：

- 代理列表：原代理池管理能力。
- 代理网关：配置 HTTP / SOCKS5 / Mixed 入口端口，并在网关详情下维护用户名路由、安全策略和 DNS 策略。
- 网关用户：维护独立代理访问账号、可用网关授权和账号级调度策略。
- 分组与标签：独立维护网关用户分组和标签。
- 网关日志：查看访问日志和配置审计。
- 运行状态：查看监听是否运行、活跃连接和累计流量。

## 配置流程

1. 在“代理列表”中维护可用上游代理。
2. 在“代理网关”中创建网关监听端口，并选择是否设为默认网关：
   - `HTTP`：仅接受 HTTP 代理请求。
   - `SOCKS5`：仅接受 SOCKS5 请求。
   - `Mixed`：同一端口同时支持 HTTP 和 SOCKS5。
   - 如果部署在 Docker、Kubernetes 或负载均衡后面，外部访问端口可以单独填写，例如容器内监听 `18080`，公网暴露 `32027`。
3. 在该网关详情中维护安全策略和 DNS 策略。每个网关都有自己的默认策略。
4. 如需让用户按需切换路由策略，在该网关详情的“用户名路由”中创建策略，并记录页面显示的标志号。
5. 在“分组与标签”中维护网关用户分组和标签。
6. 在“网关用户”中创建独立账号，选择该用户可使用的网关，并配置代理选择范围、算法、fallback、粘性策略和限速。
7. 如需智能用户名路由，开启“允许用户名携带路由标志”，并授权可使用的路由策略。默认不允许任何路由标志。
8. 点击“热加载”，使监听配置立即生效。
9. 在“运行状态”和“网关日志”中确认连接与策略命中情况。

## 智能用户名路由

用户名路由策略属于具体网关，用于“同一个网关用户，根据用户名后缀切换不同代理池或调度算法”。策略在所属网关内有一个唯一标志号，例如 `17`。用户连接代理时可使用下面任一种格式：

```text
proxy_user#17
proxy_user?route=17
proxy_user?rs=17
proxy_user?strategy=17
```

`#` 格式还支持附加参数，参数会写入访问日志便于排查：

```text
proxy_user#17;purpose=batch-a
```

权限控制规则：

- 代理账号必须开启“允许用户名携带路由标志”。
- 代理账号必须被授权使用当前连接的网关。
- 代理账号必须被授权使用该路由策略，或显式开启“允许全部路由策略”。
- 未授权、停用、不存在，或不属于当前网关的标志号会被拒绝认证。
- 未携带标志号时，仍使用代理账号自身的默认代理选择策略。
- 路由策略只覆盖本次连接的代理选择、fallback、安全策略和 DNS 策略，不会修改账号本身配置。

## 客户端示例

HTTP CONNECT:

```bash
curl -x http://127.0.0.1:18080 --proxy-user 'proxy_user:proxy_password' https://example.com
```

HTTP CONNECT 使用用户名路由策略：

```bash
curl -x http://127.0.0.1:18080 --proxy-user 'proxy_user#17:proxy_password' https://example.com
```

SOCKS5:

```bash
curl --socks5 127.0.0.1:18081 --proxy-user 'proxy_user:proxy_password' https://example.com
```

SOCKS5 使用用户名路由策略：

```bash
curl --socks5 127.0.0.1:18081 --proxy-user 'proxy_user#17:proxy_password' https://example.com
```

Mixed 监听端口也可以同时承接上面两种客户端，只要客户端协议本身正确。

## 安全建议

- 默认不要开启公网监听。若必须对外开放，先配置来源 CIDR allowlist，并在外层叠加防火墙或网关访问控制。
- 不建议默认允许直连 fallback。只有在业务明确接受“绕过上游代理”时再开启。
- 对敏感目标使用目标 Host allowlist 或 denylist，避免代理入口被滥用。
- 保持内网、回环、metadata 阻断开启，降低 SSRF 风险。
- 对外部账号设置最大并发、每分钟连接数、最大会话时长和必要的过期时间。
- 对智能用户名路由使用最小授权：只给账号授权业务需要的标志号。

## 热加载行为

- 新增或启用监听：热加载后开始绑定端口。
- 修改监听端口、监听 IP、协议、安全策略、DNS 策略：热加载后重建对应监听。
- 停用或删除监听：热加载后关闭对应端口。
- 账号、安全策略、DNS 策略更新后，新的连接会读取最新配置；已建立的长连接不会被强制中断。

## 日志和排查

- 访问日志记录账号、客户端、目标、上游代理、状态、错误、字节数、耗时、安全策略和 DNS 策略。
- 使用智能用户名路由时，访问日志会记录原始用户名、路由策略 ID、路由标志号和附加参数。
- 配置审计记录监听启动、启动失败、热加载、账号/策略变更等管理操作。
- 如果监听无法启动，优先检查端口是否被占用、监听 IP 是否允许公网绑定、系统权限是否允许绑定该端口。
- 如果目标访问失败，检查代理池中是否有可用上游代理、账号策略是否筛掉了全部代理、目标是否被安全策略或 DNS 策略拒绝。
