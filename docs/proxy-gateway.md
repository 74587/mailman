# Proxy Gateway

Proxy Gateway 让 Mailman 作为一个独立的 HTTP / SOCKS5 代理入口，对外暴露监听端口，实际访问目标时再按代理池策略选择上游代理。代理访问账号独立于 Mailman 登录账号，适合给外部工具、浏览器、爬虫或自动化任务分配受控代理能力。

> 这篇文档是功能概要。完整的手把手配置和接入手册见：[代理池管理模块接入手册](./proxy-pool-management-guide.md)。

## 功能范围

- 支持 HTTP 代理、SOCKS5 代理、Mixed 混合监听。Mixed 会通过首字节自动识别 SOCKS5，其余按 HTTP 代理处理。
- 支持监听配置热加载。新增、更新、停用监听后可在页面点击“热加载”，不需要重启 Mailman 主服务。
- 支持独立网关用户：用户名、密码、备注、分组、标签、启用状态、过期时间，并可授权可使用的网关。
- 支持为网关用户选择代理策略来源：新用户默认遵循网关目标路由和默认出口；存量用户继续使用账号独立代理策略。
- 兼容按账号配置代理选择策略：全部可用、按代理分组/标签过滤、显式临时代理池。
- 支持调度算法：随机、轮询、权重随机、最低延迟、优先复用最近成功代理。
- 支持 fallback 策略：中断、重试换代理、备用池、允许直连 fallback。
- 支持目标路由级失败切换：主出口耗尽内部重试后切到显式兜底出口，并按目标缓存不可达状态，以有上限的指数退避进行恢复探测。
- 支持粘性策略：账号、客户端 IP、目标域名、客户端 IP + 目标域名。
- 支持网关级安全边界策略：来源 CIDR、目标 Host、目标端口、内网/回环/链路本地/多播/metadata 地址阻断。
- 支持网关级 DNS 策略：远端解析、本地解析、自定义 resolver、缓存 TTL、失败 TTL、多 IP 安全检查策略。
- 支持访问日志、配置审计日志、运行状态查看。
- 支持两种智能用户名语义：新模式用用户名后缀选择目标路由最终代理池中的第 N 个代理；兼容模式继续按策略标志号切换出口策略。

## 菜单入口

代理相关能力已从“邮箱运营”菜单中独立出来，位于“代理池管理”菜单组：

- 代理列表：原代理池管理能力。
- 代理网关：配置 HTTP / SOCKS5 / Mixed 入口端口，并在网关详情下维护用户名路由、安全策略和 DNS 策略。
- 网关用户：维护独立代理访问账号、可用网关授权、代理策略来源和使用限制。
- 分组与标签：独立维护网关用户分组和标签。
- 网关日志：查看访问日志和配置审计。
- 运行状态：查看监听是否运行、活跃连接和累计流量。

## 配置流程

1. 在“代理列表”中维护可用上游代理。
2. 在“代理网关”中创建网关监听端口，并选择是否设为默认网关：
   - `HTTP`：仅接受 HTTP 代理请求。
   - `SOCKS5`：仅接受 SOCKS5 请求。
   - `Mixed`：同一端口同时支持 HTTP 和 SOCKS5。
   - 如果部署在 Docker、Kubernetes 或负载均衡后面，外部访问端口可以单独填写，例如容器内监听 `18080`，公网暴露 `32027`。
3. 在该网关详情中维护安全策略和 DNS 策略。每个网关都有自己的默认策略。
4. 在该网关详情中创建出口策略，并配置代理池、池内索引越界方式和目标路由。
5. 在“分组与标签”中维护网关用户分组和标签。
6. 在“网关用户”中创建独立账号，选择可使用的网关和代理策略来源；只有兼容模式需要配置账号自己的代理范围、算法和 fallback。
7. 如需智能用户名路由，开启智能用户名后缀。新账号选择“池内代理索引”；存量兼容账号可继续使用“策略编号”。
8. 点击“热加载”，使监听配置立即生效。
9. 在“运行状态”和“网关日志”中确认连接与策略命中情况。

## 智能用户名路由

智能用户名支持两种账号级模式。

“池内代理索引”是新账号的推荐模式。目标路由先根据目标域名或 IP 选定出口策略及代理池，用户名中的正整数再选择最终代理池的第 N 个代理（从 1 开始）：

```text
proxy_user#1
proxy_user#2
proxy_user?index=2
proxy_user?proxy=2
proxy_user?pi=2
```

例如目标路由把请求送入 `v6池`，则 `#1`、`#2` 分别表示该池的第一个和第二个代理，并不表示出口策略标志号。显式临时代理池按 `proxyIds` 的保存顺序编号；“全部可用”和“按组/标签”代理池按代理 ID 升序编号，确保相同配置下索引稳定。

每个出口策略都可配置索引越界方式。“拒绝连接”会拒绝超出池大小的索引；“取模循环”按 `((N - 1) % 池大小) + 1` 映射。例如池大小为 10 时，`#20` 映射到第 10 个代理，`#21` 映射到第 1 个代理。账号使用自己的代理池时，使用账号上的越界配置；目标路由选中出口策略时，使用该出口策略的配置。

“策略编号”是存量数据的兼容模式。此时后缀继续表示出口策略标志号：

```text
proxy_user#17
proxy_user?route=17
proxy_user?router=17
proxy_user?rs=17
proxy_user?strategy=17
```

`#` 是兼容旧数据的默认分隔符。可以在网关编辑页的“智能用户名分隔符”中每行配置一个符号分隔符，例如 `#`、`~`、`--`；一个网关最多支持 8 个，解析时较长的分隔符优先。分隔符不能包含 ASCII 冒号，因为 HTTP Basic 用户名不能包含冒号。`route`、`router`、`rs`、`strategy` 始终显式表示策略编号；`index`、`proxy`、`pi` 始终显式表示池内代理索引，不受自定义分隔符影响。

`#` 格式还支持附加参数，参数会写入访问日志便于排查：

```text
proxy_user#17;purpose=batch-a
```

权限控制规则：

- 代理账号必须开启智能用户名后缀。
- 代理账号必须被授权使用当前连接的网关。
- 策略编号兼容模式下，账号必须被授权使用该路由策略，或显式开启“允许全部路由策略”。
- 池内索引模式下，索引必须为正整数；池为空或严格模式越界时连接失败。
- 未携带智能后缀且目标路由未决定出口时，“遵循网关配置”的用户使用网关默认出口，“独立代理策略”的用户使用账号自己的配置。
- 路由策略只覆盖本次连接的代理选择、fallback、安全策略和 DNS 策略，不会修改账号本身配置。
- 目标路由启用失败切换时，池内索引会原样传给兜底出口；主、兜底出口分别按自己的代理池大小和索引越界规则处理。

开启智能用户名路由后，网关用户列表会显示“批量导出智能路由代理”操作。生成数量就是最终导出的配置条数，HTTP / SOCKS5 协议为单选。池内索引模式可顺序生成 `1..N`，也可生成 N 个不重复随机正整数；随机数可能超过池大小，应配合出口策略的“取模循环”。兼容模式仍按已授权策略编号导出。导出支持标准代理 URL、`用户:密码@地址:端口`、`地址:端口:用户:密码`、`地址:端口@用户:密码`、`用户:密码:地址:端口`、CSV、TSV 和 JSON Lines；标准 URL 会自动编码用户名和密码，IPv6 地址会自动加方括号。

## 客户端示例

HTTP CONNECT:

```bash
curl -x http://127.0.0.1:18080 --proxy-user 'proxy_user:proxy_password' https://example.com
```

HTTP CONNECT 选择最终代理池的第 2 个代理：

```bash
curl -x http://127.0.0.1:18080 --proxy-user 'proxy_user#2:proxy_password' https://example.com
```

SOCKS5:

```bash
curl --socks5 127.0.0.1:18081 --proxy-user 'proxy_user:proxy_password' https://example.com
```

SOCKS5 选择最终代理池的第 2 个代理：

```bash
curl --socks5-hostname 127.0.0.1:18081 --proxy-user 'proxy_user#2:proxy_password' https://example.com
```

Mixed 监听端口也可以同时承接上面两种客户端，只要客户端协议本身正确。

## 安全建议

- 默认不要开启公网监听。若必须对外开放，先配置来源 CIDR allowlist，并在外层叠加防火墙或网关访问控制。
- 不建议默认允许直连 fallback。只有在业务明确接受“绕过上游代理”时再开启。
- 对敏感目标使用目标 Host allowlist 或 denylist，避免代理入口被滥用。
- 保持内网、回环、metadata 阻断开启，降低 SSRF 风险。
- 对外部账号设置最大并发、每分钟连接数、最大会话时长和必要的过期时间。
- 兼容策略编号模式使用最小授权；池内索引模式按业务选择严格越界或取模循环。

## 热加载行为

- 新增或启用监听：热加载后开始绑定端口。
- 修改监听端口、监听 IP、协议、安全策略、DNS 策略：热加载后重建对应监听。
- 停用或删除监听：热加载后关闭对应端口。
- 账号、安全策略、DNS 策略更新后，新的连接会读取最新配置；已建立的长连接不会被强制中断。

## 日志和排查

- 访问日志记录账号、客户端、目标、上游代理、状态、错误、字节数、耗时、安全策略和 DNS 策略。
- 使用智能用户名路由时，访问日志会记录原始用户名、最终路由策略、请求索引、取模后的索引、代理池大小和附加参数。
- 配置审计记录监听启动、启动失败、热加载、账号/策略变更等管理操作。
- 如果监听无法启动，优先检查端口是否被占用、监听 IP 是否允许公网绑定、系统权限是否允许绑定该端口。
- 如果目标访问失败，检查代理池中是否有可用上游代理、账号策略是否筛掉了全部代理、目标是否被安全策略或 DNS 策略拒绝。
